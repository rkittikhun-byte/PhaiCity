# แกนของเกม (Core design)

เจ้าของ 13 ต.ค. 2026: "ฉันเลยจะเขียน core เกมส์ยังไง ให้มันได้ครอบคลุมได้ทั้งเกมส์" และ "เขียน เป็น class หรือ object
กลางไว้ แล้ว อื่นๆ ก็แตก object ออกไป" แผนทั้งเกมอยู่ใน `docs/GAME_PLAN.md` เอกสารนี้อธิบายโครงที่ทุกเฟสยืนอยู่

## 1. ภาพรวม

```
        ผู้เล่น (คลิก กดปุ่ม)               server (ภายหลัง: รันเมืองซ้ำเพื่อตรวจ)
            │ คำสั่ง (Command)                  │ คำสั่งชุดเดียวกัน
            ▼                                   ▼
┌──────────────── CityCore (src/core/cityCore.ts) ไม่มี DOM ────────────────┐
│ World: แผนที่และชั้นข้อมูลข้างไทล์ │ simulation │ ทะเบียนวัตถุ │ Random  │
│ Objects: CityObject → Building → CommunityBuilding / CentralService …  │
│ Systems: simulation หนึ่ง step แล้วระบบตามลำดับตายตัว                    │
│ Log: คำสั่งที่รับ พร้อม step ที่รับ                                         │
└───────────────────────────────────────────────────────────────────────┘
            │ เหตุการณ์ (simulation messages, ภายหลัง: events ของ core)
            ▼
   Views: 3D │ การ์ด │ แผนที่เมือง │ เสียง │ ข่าว   อ่านอย่างเดียว ไม่เขียนกลับ
   Data:  ตารางตัวเลขของแต่ละชนิด (ราคา ค่าบำรุง ที่รับได้ …) และกติกาจังหวัด (data/province-rules.json)
```

**ใครใช้ core:** เกมในเบราว์เซอร์ (`src/game.js`), เทสต์ (`test/cityCore.ts`, `test/playthrough.ts`),
ตัววัดความเร็ว (`test/coreBenchmark.ts`) และภายหลัง Web Worker กับ server ทุกที่สร้างเมืองด้วยวิธีเดียวกัน
คำสั่งเดียวกันจึงให้ผลเหมือนกันทุกที่

## 2. ส่วนต่างๆ และไฟล์

| ส่วน | หน้าที่ | ไฟล์ |
|---|---|---|
| **World** | ทุกอย่างของเมือง: แผนที่ ชั้นข้อมูลข้างไทล์ (ชนิดโรงไฟฟ้า ระดับถนน ที่ว่าการ ที่ดิน …) simulation วัตถุ | `src/core/cityCore.ts`, `src/core/cityLayers.ts` |
| **Objects** | ทุกสิ่งที่คลิกได้เป็นคลาส แต่ละชนิดรู้ข้อมูลของตัวเอง (facts) และภายหลังความพอใจ | `src/objects/` |
| **Systems** | กติกาที่เกี่ยวกับหลายวัตถุ รันตามลำดับตายตัว | `CitySystem` ใน `cityCore.ts` (ตอนนี้: `objects`) และระบบเดิมใน `simulation.js` |
| **Commands** | ทางเดียวที่ผู้เล่นเปลี่ยนเมืองได้ ตรวจก่อนเปลี่ยน และบันทึกลง log | `src/cityCommands.ts`, `CityCore.apply` |
| **Events** | core ประกาศว่าเกิดอะไรขึ้น ให้หน้าจอ เสียง และข่าวฟังเอง | ตอนนี้ใช้ message ของ simulation (`src/messages.ts`) |
| **Views** | วาดและแสดง อ่าน World อย่างเดียว | `src/render3d/`, การ์ด, `src/cityMap.ts`, `src/audio/` |
| **Data** | ตัวเลขของแต่ละชนิดแยกจากโค้ด | ตาราง `*_SPECS` ในแต่ละโมดูล, `data/province-rules.json` |

## 3. ลำดับใน CityCore

- `new CityCore(setup)`:
  1. seed `Random` (เมืองใหม่ที่ให้ seed มา)
  2. อ่านชั้นข้อมูลข้างไทล์จากเซฟ หรือเริ่มใหม่ (`readCityLayers`)
  3. สร้าง simulation และโหลดเซฟ
  4. สร้างเครื่องมือ คำสั่ง (`commandTarget`) และทะเบียนวัตถุ
  5. ลงระบบ `objects`
- `apply(command)`: ตรวจและทำคำสั่ง ถ้ารับก็บันทึก `{ step, command }` ลง `log`
- `step()`: simulation หนึ่ง step แล้วเดินเวลา พอขึ้นเดือนใหม่ ระบบทุกตัวรันตามลำดับที่ลงไว้ (`monthly`)
- `tick(now)`: ลูปของเบราว์เซอร์ เดินหนึ่ง step เมื่อถึงเวลาตามความเร็ว (ช้า 100 ms กลาง 50 ms เร็ว 10 ms)
- `save()`: ชั้นข้อมูลข้างไทล์ วัตถุ เครื่องมือ และ simulation ส่วนที่เกมเก็บเอง (ชื่อเมือง ยศ ข่าว ภารกิจ)
  `game.js` เติมทีหลัง

หนึ่งปีของเกมคือ 48 หน่วยเวลา × 16 step = 768 step (`STEPS_PER_YEAR`)

## 4. กฎที่ทำให้เมืองรันซ้ำได้ผลเดิม

ใช้สำหรับเกมออนไลน์: server เอา seed กับ log ไปรันซ้ำแล้วต้องได้เมืองเดียวกันเป๊ะ (`test/cityCore.ts` ตรวจข้อนี้)

1. **สุ่มจาก `Random` ตัวเดียวเท่านั้น** ห้าม `Math.random` และห้ามใช้เวลาของเครื่องในกติกา
   (ใช้นาฬิกาได้เฉพาะการเว้นระยะข้อความเตือน ซึ่งไม่เปลี่ยนเมือง)
2. **แผนที่จริงออกมาเหมือนเดิมทุกครั้ง:** `MapGenerator.fromPresetCells` เกลี่ยขอบแม่น้ำด้วย seed ของตัวเอง
   และคืนสถานะ `Random` ของเกม (แก้ 13 ต.ค. 2026 เพราะเคยทำให้แผนที่ขอนแก่นต่างกันทุกครั้งที่สร้าง)
3. **คำสั่งเข้าทาง `apply` เท่านั้น** และ log บอก step ที่รับ
4. **ระบบรันตามลำดับตายตัว** วนวัตถุตามลำดับดัชนีเสมอ ไม่วนตามลำดับที่ไม่แน่นอน
5. **ยังเหลือ:** sprite (รถไฟ เครื่องบิน เรือ) ยังสุ่มจาก `Random` ทุกเฟรมภาพในเบราว์เซอร์ เมืองในเบราว์เซอร์จึงยัง
   รันซ้ำทีละ tick ไม่ได้ ต้องย้ายการขยับ sprite เข้าไปใน step (เฟส 0 ส่วนต่อไป)

## 5. วัตถุ

```
CityObject (ตำแหน่ง ขนาด ชนิด facts)
 ├─ Building (ปีที่สร้าง ไฟ น้ำ ฝั่ง)
 │   ├─ CommunityBuilding  ชุมชน: บ้าน ร้าน โรงงาน ไร่นา ท่าประมง (และโรงแรม)
 │   └─ CentralService     ส่วนกลาง: ไฟ น้ำ ขยะ โรงเรียน โรงพยาบาล ตำรวจ ดับเพลิง สถานี เหมือง (สัมปทาน) ที่ว่าการ
 ├─ Vehicle (เฟส 7)        รถขยะ รถพยาบาล รถดับเพลิง รถสายตรวจ รถเมล์ สองแถว เรือประมง รถส่วนตัว
 └─ วัตถุอื่น (เฟส 7)       ถนน (ชื่อจาก src/streetNames.ts) ป่า น้ำ ที่ดิน
```

- **หาวัตถุจากไทล์:** `buildingAt` อ่านช่องกลางของโซน (ZONEBIT) ไทล์เดี่ยว และแปลงที่ระบายสี
- **ทะเบียน `CityObjects`:** สแกนทั้งแผนที่ทุกเดือน (400×400 ใช้ราว 4 ms) วัตถุที่ยังอยู่เก็บของเดิมไว้
  วัตถุใหม่ได้เวลาสร้าง วัตถุที่หายไปถูกตัดออก และทุกไทล์รู้ว่าเป็นของวัตถุไหน
- **เซฟเก็บเฉพาะที่ไทล์บอกไม่ได้:** ตอนนี้คือเวลาสร้าง เก็บแบบแบน `[id, built, …]`
  ภายหลังเพิ่มชื่อ รถ และบัญชี
- **ฝั่ง:** `sector` = `community` หรือ `central` (`docs/GAME_PLAN.md` ข้อ 12–13)

**เพิ่มวัตถุชนิดใหม่:**
1. คลาสใน `src/objects/` ใต้ฝั่งของมัน
2. หาได้จากไทล์ใน `buildingAt`
3. แถวในตารางตัวเลขของชนิดนั้น
4. โมเดล 3D และคำแปล `object.kind.*`
5. เทสต์ใน `test/cityObjects.ts`

## 6. ระบบ

ตอนนี้ simulation เดิมของ micropolis ทำงานเป็นก้อนเดียวใน `step()` (16 phase ต่อหน่วยเวลา: ไฟ น้ำ จราจร การโต
ภาษี …) แล้ว core รันระบบของตัวเองต่อท้ายตามลำดับ:

| ลำดับ | ระบบ | สถานะ |
|---|---|---|
| 1 | simulation เดิม (ทั้งก้อน) | มีแล้ว |
| 2 | `objects`: สแกนวัตถุ | มีแล้ว |
| 3 | ทรัพยากรรายช่อง | เฟส 5 |
| 4 | ครัวเรือน งาน โรงเรียน | เฟส 7 |
| 5 | การเดินทางและรถ | เฟส 7 |
| 6 | บริการส่งรถ | เฟส 7 |
| 7 | เงินรายอาคาร | เฟส 7 |
| 8 | ความพอใจ | เฟส 7 |
| 9 | โต ทรุด ย้ายออก (แทนการโตเดิม) | เฟส 7 |

**เปลี่ยนจาก micropolis ทีละระบบ (strangler pattern):**
1. ดึงระบบเดิมออกจากก้อน simulation มาเป็น `CitySystem` ทีละตัว เกมยังเล่นได้
2. เปลี่ยนไส้ในของระบบนั้นเป็นของใหม่ เช่น การโตเดิมเป็นระบบความพอใจ หรือจราจรเดิมเป็นระบบการเดินทาง
3. ทุกครั้งต้องผ่าน `test/cityCore.ts` (รันซ้ำได้ผลเดิม) `test/playthrough.ts` (เล่นยาว 10 ปี บันทึก เปิดซ้ำ)
   และวัดความเร็วด้วย `test/coreBenchmark.ts`

**เพิ่มระบบใหม่:** เขียน `CitySystem` (`name`, `monthly`) แล้ว `core.addSystem` ตามลำดับในตาราง
ระบบอ่านและเขียน World ได้ แต่ไม่แตะ DOM

## 7. ความเร็ว

`CORE_BENCH=1 npx jest test/coreBenchmark.ts --coverage=false` วัดแผนที่เมืองขอนแก่น 400×400 ไม่มีหน้าจอ

| วันที่ | เมือง | สร้างเมือง | 1 เดือน | 1 ปี | สแกนวัตถุ |
|---|---|---|---|---|---|
| 13 ต.ค. 2026 | ว่าง (เพิ่งเริ่ม) | 304 ms | 80 ms (ช้าสุด 143) | 1.0 s | 4 ms |

ที่ความเร็วเร็วสุด เบราว์เซอร์เดินหนึ่ง step ทุก 10 ms หนึ่งเดือนจึงเป็นราว 0.64 วินาทีของเวลาจริง
การจำลองตอนนี้กินราว 12% ของเวลานั้น ส่วนที่เหลือใช้เพิ่มคนกับรถในเฟส 7 ได้ (งบ: `docs/GAME_PLAN.md` หัวข้อ 6)

## 8. ต่อไปในเฟส 0

1. ย้ายการขยับ sprite เข้า step ให้เบราว์เซอร์รันซ้ำทีละ tick ได้ (ข้อ 4.5)
2. events ของ core เอง (สร้าง รื้อ ขึ้นเดือน ไฟไหม้ …) เป็นข้อมูลธรรมดา ให้หน้าจอฟัง แทนการผูกกับ simulation ตรงๆ
3. ตัวรันเมืองแบบเล่นอัตโนมัติหลายปี พร้อมเช็กสมดุลเงินและคุณสมบัติที่ต้องจริงเสมอ
4. ย้าย core ไปรันใน Web Worker ส่วนหน้าจอได้ภาพของ World ทีละเฟรม (เมื่อเฟส 7 เริ่มหนัก)
