# แกนของเกม (Core design)

เจ้าของ 13 ต.ค. 2026: "ฉันเลยจะเขียน core เกมส์ยังไง ให้มันได้ครอบคลุมได้ทั้งเกมส์" และ "เขียน เป็น class หรือ object
กลางไว้ แล้ว อื่นๆ ก็แตก object ออกไป" แผนทั้งเกมอยู่ใน `docs/GAME_PLAN.md` เอกสารนี้อธิบายโครงที่ทุกเฟสยืนอยู่

## 1. ภาพรวม

```
        ผู้เล่น (คลิก กดปุ่ม)               server (ภายหลัง: รันเมืองซ้ำเพื่อตรวจ)
            │ คำสั่ง (Command)                  │ คำสั่งชุดเดียวกัน
            ▼                                   ▼
┌──────────────── CityCore (src/core/cityCore.ts) ไม่มี DOM ────────────────┐
│ World: แผนที่และชั้นข้อมูลข้างไทล์ │ simulation │ ทะเบียนวัตถุ │ Random  │
│ Objects: CityObject → Building → CommunityBuilding / CentralService …  │
│ Systems: simulation หนึ่ง step แล้วระบบตามลำดับตายตัว                    │
│ Log: คำสั่งที่รับ พร้อม step ที่รับ                                         │
└───────────────────────────────────────────────────────────────────────┘
            │ เหตุการณ์ (events ของ core `CoreEvent` และ simulation messages)
            ▼
   Views: 3D │ การ์ด │ แผนที่เมือง │ เสียง │ ข่าว   อ่านอย่างเดียว ไม่เขียนกลับ
   Data:  ตารางตัวเลขของแต่ละชนิด (ราคา ค่าบำรุง ที่รับได้ …) และกติกาจังหวัด (data/province-rules.json)
```

**ใครใช้ core:** เกมในเบราว์เซอร์ (`src/game.js`), เทสต์ (`test/cityCore.ts`, `test/playthrough.ts`),
ตัววัดความเร็ว (`test/coreBenchmark.ts`), ผู้เล่นอัตโนมัติ (`src/core/autoPlayer.ts`) และภายหลัง Web Worker กับ server
ทุกที่สร้างเมืองด้วยวิธีเดียวกัน คำสั่งเดียวกันจึงให้ผลเหมือนกันทุกที่

## 2. ส่วนต่างๆ และไฟล์

| ส่วน | หน้าที่ | ไฟล์ |
|---|---|---|
| **World** | ทุกอย่างของเมือง: แผนที่ ชั้นข้อมูลข้างไทล์ (ระดับถนน ที่ว่าการ ที่ดิน …) ถนนและรางที่วาดเป็นเมตร (`gameMap.roadGraph`, `railGraph`) อาคารของเจ้าเมืองพร้อมชนิดและระดับ (`gameMap.buildings`, `docs/METRE_DRAWING_PLAN.md` 2.6) simulation วัตถุ | `src/core/cityCore.ts`, `src/core/cityLayers.ts`, `src/roads/`, `src/buildings/` |
| **Objects** | ทุกสิ่งที่คลิกได้เป็นคลาส แต่ละชนิดรู้ข้อมูลของตัวเอง (facts) และความพอใจ (แสดงในการ์ดและชั้นแผนที่อย่างเดียว ยังไม่คุมการโต) | `src/objects/` |
| **Systems** | กติกาที่เกี่ยวกับหลายวัตถุ รันตามลำดับตายตัว | `CitySystem` ใน `cityCore.ts` (ตอนนี้: `objects`, `era`, `festivals`) และระบบเดิมใน `simulation.js` |
| **Commands** | ทางเดียวที่ผู้เล่นเปลี่ยนเมืองได้ ตรวจก่อนเปลี่ยน และบันทึกลง log | `src/cityCommands.ts`, `CityCore.apply` |
| **Events** | core ประกาศว่าเกิดอะไรขึ้น ให้หน้าจอ เสียง และข่าวฟังเอง | `CoreEvent` กับ `on`/`emit` ใน `cityCore.ts` (ขึ้นเดือน สร้าง รื้อ คำสั่ง ยุค เทศกาล) และ message ของ simulation (`src/messages.ts`) ที่ยังใช้คู่กัน |
| **Views** | วาดและแสดง อ่าน World อย่างเดียว | `src/render3d/`, การ์ด, `src/cityMap.ts`, `src/audio/` |
| **Data** | ตัวเลขของแต่ละชนิดแยกจากโค้ด | ตาราง `*_SPECS` ในแต่ละโมดูล, `data/province-rules.json` |

## 3. ลำดับใน CityCore

- `new CityCore(setup)`:
  1. seed `Random` (เมืองใหม่ที่ให้ seed มา)
  2. อ่านชั้นข้อมูลข้างไทล์จากเซฟ หรือเริ่มใหม่ (`readCityLayers`)
  3. สร้าง simulation และโหลดเซฟ
  4. เติมชั้นข้อมูลที่ขาด (`ensureCityLayers`) ใส่อาคารของเจ้าเมืองจากเซฟเก่าลง `gameMap.buildings` ครั้งเดียว
     (`completeBuildings`) และให้เมืองที่ทาโซนทีละช่องย่อยได้แปลงของมัน (`syncCellPlots`)
  5. สร้างเครื่องมือ คำสั่ง (`commandTarget`) และทะเบียนวัตถุ
  6. ลงระบบ `objects`, `era`, `festivals` ตามลำดับนี้
- `apply(command)`: ตรวจและทำคำสั่ง ถ้ารับก็บันทึก `{ step, command }` ลง `log` และประกาศ event `command`
- `step()`: simulation หนึ่ง step แล้วเดินเวลา พอขึ้นเดือนใหม่ ระบบทุกตัวรันตามลำดับที่ลงไว้ (`monthly`)
  แล้วประกาศ event `month`
- `tick(now)`: ลูปของเบราว์เซอร์ เดินหนึ่ง step เมื่อถึงเวลาตามความเร็ว (ช้า 100 ms กลาง 50 ms เร็ว 10 ms
  คือ 1× 2× 3× ของแถบเวลา `src/timeControls.ts`)
- `save()`: ชั้นข้อมูลข้างไทล์ (รวมกราฟถนนและราง `roads`/`rails` และอาคารของเจ้าเมือง `buildings`) วัตถุ เครื่องมือ
  และ simulation ส่วนที่เกมเก็บเอง (ชื่อเมือง ยศ ข่าว ภารกิจ) `game.js` เติมทีหลัง

หนึ่งปีของเกมคือ 48 หน่วยเวลา × 16 step = 768 step (`STEPS_PER_YEAR`)

## 4. กฎที่ทำให้เมืองรันซ้ำได้ผลเดิม

ใช้สำหรับเกมออนไลน์: server เอา seed กับ log ไปรันซ้ำแล้วต้องได้เมืองเดียวกันเป๊ะ (`test/cityCore.ts` ตรวจข้อนี้)

1. **สุ่มจาก `Random` ตัวเดียวเท่านั้น** ห้าม `Math.random` และห้ามใช้เวลาของเครื่องในกติกา
   (ใช้นาฬิกาได้เฉพาะการเว้นระยะข้อความเตือน ซึ่งไม่เปลี่ยนเมือง)
2. **แผนที่จริงออกมาเหมือนเดิมทุกครั้ง:** `MapGenerator.fromPresetCells` เกลี่ยขอบแม่น้ำด้วย seed ของตัวเอง
   และคืนสถานะ `Random` ของเกม (แก้ 13 ต.ค. 2026 เพราะเคยทำให้แผนที่ขอนแก่นต่างกันทุกครั้งที่สร้าง)
3. **คำสั่งเข้าทาง `apply` เท่านั้น** และ log บอก step ที่รับ
4. **ระบบรันตามลำดับตายตัว** วนวัตถุตามลำดับดัชนีเสมอ ไม่วนตามลำดับที่ไม่แน่นอน
5. **ยังเหลือ:** sprite (รถไฟ เครื่องบิน เรือ) ยังสุ่มจาก `Random` ทุกเฟรมภาพในเบราว์เซอร์ เมืองในเบราว์เซอร์จึงยัง
   รันซ้ำทีละ tick ไม่ได้ ต้องย้ายการขยับ sprite เข้าไปใน step (เฟส 0 ส่วนต่อไป)

## 5. วัตถุ

```
CityObject (ตำแหน่ง ขนาด ชนิด facts)
 ├─ Building (ปีที่สร้าง ไฟ น้ำ ฝั่ง และตำแหน่งเมตร `placed` ของอาคารที่เครื่องมือวาง)
 │   ├─ CommunityBuilding  ชุมชน: บ้าน ร้าน โรงงาน ไร่นา ท่าประมง (และโรงแรม)
 │   └─ CentralService     ส่วนกลาง: ไฟ น้ำ ขยะ โรงเรียน โรงพยาบาล ตำรวจ ดับเพลิง สถานี เหมือง (สัมปทาน) ที่ว่าการ
 ├─ RoadSegment (มีแล้ว)   ถนนจากแยกถึงแยก (src/objects/roadSegment.ts) ชื่อจาก src/streetNames.ts
 │                          หาจากช่องถนนทุกครั้งที่คลิก ไม่อยู่ในทะเบียนและไม่ต้องเก็บในเซฟ
 ├─ Vehicle (เฟส 7)        รถขยะ รถพยาบาล รถดับเพลิง รถสายตรวจ รถเมล์ สองแถว เรือประมง รถส่วนตัว
 └─ วัตถุอื่น (เฟส 7)       ป่า น้ำ ที่ดิน
```

- **หาวัตถุ:** อาคารที่เครื่องมือวางมาจากรายการ `gameMap.buildings` พร้อมตำแหน่งเมตร มุม และเครื่องมือที่สร้าง
  (`Building.placed`, `docs/METRE_DRAWING_PLAN.md` 2.7) ย้ายแล้วยังเป็นวัตถุเดิม ส่วนบ้าน ร้าน โรงงาน และป้ายรถ
  ยังหาจากไทล์ด้วย `buildingAt` (ช่องกลางของโซน (ZONEBIT) ไทล์เดี่ยว และแปลงที่ระบายสี) จนกว่าโซนจะเป็นเมตร
- **ทะเบียน `CityObjects`:** สแกนทั้งแผนที่ทุกเดือน (400×400 ใช้ราว 4 ms วัด 13 ต.ค. 2026) วัตถุที่ยังอยู่เก็บของเดิมไว้
  วัตถุใหม่ได้เวลาสร้าง วัตถุที่หายไปถูกตัดออก และทุกไทล์รู้ว่าเป็นของวัตถุไหน
- **เซฟเก็บเฉพาะที่ไทล์บอกไม่ได้:** ของวัตถุคือเวลาสร้าง เก็บแบบแบน `[id, built, …]` (ชนิดและระดับของอาคาร
  เจ้าเมืองเก็บกับ `buildings` ไม่ใช่กับวัตถุ) ภายหลังเพิ่มชื่อ รถ และบัญชี
- **ฝั่ง:** `sector` = `community` หรือ `central` (`docs/GAME_PLAN.md` ข้อ 12–13)

**เพิ่มวัตถุชนิดใหม่:**
1. คลาสใน `src/objects/` ใต้ฝั่งของมัน
2. หาได้จากไทล์ใน `buildingAt` (อาคารของเจ้าเมืองเข้า `gameMap.buildings` เองเมื่อวางผ่านคำสั่ง)
3. แถวในตารางตัวเลขของชนิดนั้น
4. โมเดล 3D และคำแปล `object.kind.*`
5. เทสต์ใน `test/cityObjects.ts`

## 6. ระบบ

ตอนนี้ simulation เดิมของ micropolis ทำงานเป็นก้อนเดียวใน `step()` (16 phase ต่อหน่วยเวลา: ไฟ น้ำ จราจร การโต
ภาษี …) แล้ว core รันระบบของตัวเองต่อท้ายตามลำดับ:

| ลำดับ | ระบบ | สถานะ |
|---|---|---|
| 1 | simulation เดิม (ทั้งก้อน) | มีแล้ว |
| 2 | `objects`: สแกนวัตถุ ประกาศ `built` / `removed` | มีแล้ว |
| 3 | `era`: คะแนนยุคและยุคของแต่ละอาคาร (`src/eraScore.ts`, `docs/GAME_DESIGN.md` ข้อ 1) ประกาศ `eraDawn` / `era` | มีแล้ว 20 ต.ค. 2026 |
| 4 | `festivals`: จัดเทศกาลตามที่เจ้าเมืองตอบ ถามเทศกาลเดือนหน้า (`src/festivals.ts`, `docs/GAME_DESIGN.md` ข้อ 5) | มีแล้ว 20 ต.ค. 2026 |
| 5 | ทรัพยากรรายช่อง | เฟส 5 |
| 6 | ครัวเรือน งาน โรงเรียน | เฟส 7 (`docs/CITIES_SKYLINES_ROADMAP.md` เฟส C.1) |
| 7 | การเดินทางและรถ | เฟส 7 (รถเป็นตัวบนกราฟถนน: `docs/METRE_DRAWING_PLAN.md` ขั้น 4) |
| 8 | บริการส่งรถ | เฟส 7 (`docs/CITIES_SKYLINES_ROADMAP.md` เฟส B.2) |
| 9 | เงินรายอาคาร | เฟส 7 |
| 10 | ความพอใจ | เฟส 7 (ตอนนี้ `src/objects/satisfaction.ts` คิดเมื่อการ์ดหรือชั้นแผนที่ขอ ยังไม่เป็นระบบ) |
| 11 | โต ทรุด ย้ายออก (แทนการโตเดิม) | เฟส 7 |

**เปลี่ยนจาก micropolis ทีละระบบ (strangler pattern):**
1. ดึงระบบเดิมออกจากก้อน simulation มาเป็น `CitySystem` ทีละตัว เกมยังเล่นได้
2. เปลี่ยนไส้ในของระบบนั้นเป็นของใหม่ เช่น การโตเดิมเป็นระบบความพอใจ หรือจราจรเดิมเป็นระบบการเดินทาง
3. ทุกครั้งต้องผ่าน `test/cityCore.ts` (รันซ้ำได้ผลเดิม) `test/playthrough.ts` (เล่นยาว 10 ปี บันทึก เปิดซ้ำ)
   และวัดความเร็วด้วย `test/coreBenchmark.ts` ส่วนสมดุลเงินและการโตดูด้วยผู้เล่นอัตโนมัติ
   (`PHAICITY_PLAY=1 npx jest --coverage=false test/play/`)

**เพิ่มระบบใหม่:** เขียน `CitySystem` (`name`, `monthly`) แล้ว `core.addSystem` ตามลำดับในตาราง
ระบบอ่านและเขียน World ได้ แต่ไม่แตะ DOM

## 7. ความเร็ว

`CORE_BENCH=1 npx jest test/coreBenchmark.ts --coverage=false` วัดแผนที่เมืองขอนแก่น 400×400 ไม่มีหน้าจอ

| วันที่ | เมือง | สร้างเมือง | 1 เดือน | 1 ปี | สแกนวัตถุ |
|---|---|---|---|---|---|
| 13 ต.ค. 2026 | ว่าง (เพิ่งเริ่ม) | 304 ms | 80 ms (ช้าสุด 143) | 1.0 s | 4 ms |

ที่ความเร็วเร็วสุด เบราว์เซอร์เดินหนึ่ง step ทุก 10 ms หนึ่งเดือนจึงเป็นราว 0.64 วินาทีของเวลาจริง
การจำลองกินราว 12% ของเวลานั้น (วัด 13 ต.ค. 2026) ส่วนที่เหลือใช้เพิ่มคนกับรถในเฟส 7 ได้
(งบ: `docs/GAME_PLAN.md` หัวข้อ 6)

ยังไม่ได้วัดซ้ำตั้งแต่ 13 ต.ค. 2026 ทั้งที่ระบบ `era` กับ `festivals` และอาคารเป็นเมตรเข้ามาแล้ว และตัววัดยังใช้แผนที่เมือง
400×400 (`data/maps/city/TH-40.json`) ขณะที่เกมเล่นกรอบของแผนที่ทั้งอำเภอ เริ่ม 480×480 ช่องและขยายตามที่ดินที่ซื้อ
(`src/cityFrame.ts`)
