# แผนเอาตารางออกจากเกม (simulation ตามของ)

เจ้านาย 21 ต.ค. 2026: "เกมส์ยังแบ่งช่องเป็นตารางอยู่ ... ถ้ามีที่ไหนมีตารางอีก งานนี้จะได้เป็นงานใหญ่ที่สุดของโปรเจกต์"

เอกสารนี้คือขั้น 4 ของ `docs/METRE_DRAWING_PLAN.md` ("simulation ตามของ") ที่ขยายเป็นแผนเต็ม เขียนโดยไม้ไผ่29
(21 ต.ค. 2026) จากการไล่โค้ดทุกไฟล์ที่ยังคิดเป็นช่อง 16 ม. แผนนี้มี 3 ส่วน:
- ตารางยังอยู่ตรงไหน
- ทำอะไรก่อนหลัง
- แต่ละขั้นใหญ่แค่ไหน

สถานะว่าทำถึงไหนอยู่ในตาราง "ความคืบหน้า" ท้ายไฟล์

---

## 1. สรุปสั้น ๆ

**ตอนนี้ (หลังแผนวาดแบบเมตรขั้น 0–3):** ถนน ราง คลอง และอาคารของเจ้าเมือง วาดและเก็บเป็นเมตรแล้ว โซนทาเป็นช่องย่อย 4 ม.
ตามถนน แต่ทุกอย่างที่ "คิด" ยังเป็นช่อง 16 ม. ของ micropolisJS:
- ระบบเปลี่ยนของที่วาดเป็นช่องก่อน แล้วค่อยคิดกับช่อง
- ผลที่ออกมาจึงเป็นสี่เหลี่ยม 16 ม. (หรือ 32 ม., 128 ม.)
- และผู้เล่นเห็นมัน

**ตัวอย่างที่ผู้เล่นเจอจริงวันนี้:**

| ผู้เล่นทำ | ผู้เล่นเห็น | เพราะ |
|---|---|---|
| วางโรงเรียนหันตามถนนเฉียง แล้ววาดถนนผ่านมุมสนามหญ้าข้าง ๆ | ถนนไม่ยอมวางตรงนั้น ทั้งที่เห็นเป็นหญ้าว่าง | ระบบจองช่อง 3×3 ตั้งตรงกับแผนที่ทั้งก้อน (48×48 ม.) มุมที่หญ้าโผล่ก็ยังเป็นของโรงเรียน |
| ทาร้านค้าแถวเดียวยาว 40 ม. ข้างถนน | ไม่มีตึกขึ้นสักหลัง | ต้องทาให้ถึง 28% ของสี่เหลี่ยม 16 ม. ก่อน ช่องย่อยจึงกลายเป็น "แปลง" |
| ร้านอยู่ห่างบ้าน 600 ม. | ระบบหาร้านไม่เจอ แต่ก็ไม่เสียอะไร | รถจำลองเดินสุ่มได้แค่ 30 ช่อง (480 ม.) แล้วยอมแพ้ |
| เปิดดูรถ | รถทั้งเมืองมี 16 คัน วิ่งบนถนนว่าง หายตรงสุดถนนแล้วโผล่อีกปลาย ไม่เลี้ยวที่แยก | รถ 3D ไม่ได้มาจากการเดินทางจริง |
| น้ำไม่พอ | บ้านฝั่งตะวันออกแห้งก่อนเสมอ | แจกน้ำตามลำดับที่สแกนแผนที่ (ซ้ายไปขวา) |
| ดูแผนที่ควัน/ราคาที่ดิน | เป็นสี่เหลี่ยม 32 ม. และ 128 ม. ขั้นบันได | ค่าเก็บเป็นบล็อก 2×2 และ 8×8 ช่อง |
| ไฟไหม้ | ไหม้ช่องเดียวแล้วดับ ไม่ลาม | โค้ดลามไฟอ่านช่องผิด (บั๊กเดิมของ micropolisJS) |

**ลำดับที่เสนอ:**

| ขั้น | งาน | ขนาด |
|---|---|---|
| 0 | เตรียมและแก้บั๊ก | ~1.5 รอบ |
| 1 | จราจรเป็นรถจริงบนกราฟถนน | ~6 รอบ |
| 2 | ไฟและน้ำไหลตามเส้นถนน | ~2.5 รอบ |
| 3 | อาคารกินที่ตามรูปฐานจริง แปลงเป็นอาคารทีละหลัง | ~7 รอบ |
| 4 | ควัน ราคาที่ดิน อาชญากรรม บริการ เป็นระยะจริง | ~3.5 รอบ |
| 5 | เลิกใช้ตารางในระบบจำลอง | ~4 รอบ |

- **รวม:** ราว 24 รอบ
- **หนึ่งรอบ:** ไม้ไผ่หนึ่งตัวทำงานในโควตา 5 ชั่วโมงหนึ่งช่วง
- **เวลา:** ถ้าทำทีละตัวราว 12 วัน ถ้าแยกทำพร้อมกันตามข้อ 7 ราว 7–8 วัน

## 2. ตารางยังอยู่ตรงไหน (ผลการตรวจ 21 ต.ค. 2026)

### 2.1 ขนาดที่ต้องคิด

| แผนที่ | ขนาด | ช่องละ |
|---|---|---|
| เกมต้นฉบับ micropolisJS | 120×100 = 12,000 ช่อง | 10 ม. |
| เมืองขอนแก่น (`data/maps/city/TH-40.json`) | 400×400 = 160,000 ช่อง | 16 ม. |
| กรอบอำเภอตอนเริ่ม (`src/cityFrame.ts`) | 480×480 = 230,400 ช่อง (7.7 กม.) | 16 ม. |
| กรอบอำเภอเต็มที่ | 1,024×1,024 ≈ 1.05 ล้านช่อง | 16 ม. |
| อำเภอเมืองขอนแก่นทั้งอำเภอ | 2,624×2,912 ≈ 7.6 ล้านช่อง (เล่นไม่ได้วันนี้) | 16 ม. |

- ทุกช่องเป็นวัตถุ JavaScript หนึ่งตัว (`src/gameMap.js`)
- ระบบเดินดูทุกช่อง 4 ครั้งต่อเดือนเกม (`mapScan` phase 1–8 ใน `src/simulation.js`):
  - กรอบเริ่มต้น: ราว 0.9 ล้านครั้งต่อเดือน
  - กรอบเต็ม: ราว 4.2 ล้านครั้ง
- ความยาวของหนึ่งเดือนเกม:
  - ราว 2 วินาทีที่ 3×
  - ราว 4 วินาทีที่ 2×

## 3. เป้าหมาย

**ของที่ผู้เล่นวาดและของที่เกิดในเมืองเป็นตัวจริง ระบบจำลองคิดกับของ ไม่ใช่กับช่อง:**

| ของ | คืออะไร | ระบบไหนใช้ |

| ถนน | เส้นในกราฟ (ทุกเส้นในเมือง รวมถนนเดิมของแผนที่) มีเลน ความเร็ว จุรถได้เท่าไร | จราจร ไฟ น้ำ ค่าบำรุง บริการ |
| อาคาร | รายการ: id, รูปฐานสี่เหลี่ยมหมุน (กลาง มุม กว้าง ลึก เมตร), ชนิด ระดับ ยุค, เส้นถนนที่หันหน้าเข้า | การเดินทาง ไฟ น้ำ ควัน ราคาที่ดิน การโต |
| แปลง | กลุ่มช่องย่อยที่ทาติดกันตามเส้นถนน กว้างหน้า × ลึก | อาคารที่โตบนนั้น |
| ค่ารอบ ๆ | คิดที่ตำแหน่งของอาคารแต่ละหลังจากแหล่งที่มีตำแหน่งและรัศมีเป็นเมตร | การโต ความพอใจ |

- **ช่องยังอยู่ระหว่างทาง** เป็นภาพย่อที่สร้างจากของ (เหมือนที่ถนนทำอยู่แล้วใน `roadRaster.ts`) ให้ระบบเก่าที่ยังไม่ได้ย้ายอ่านได้
- **ช่องหายจากระบบจำลองในขั้น 5** แต่ยังสร้างเพื่อแผนที่ย่อและหน้าจอ 2D สำรอง
- **ข้อมูลธรรมชาติยังเป็นตารางได้:** ความสูง พื้นปกคลุม และน้ำบาดาลเป็นข้อมูลของพื้นดิน (Cities: Skylines ก็เก็บพื้นเป็นตาราง)
  - วาดให้นุ่มเสมอ ไม่ให้เห็นขอบช่อง
  - ไม่ใช่ตารางที่เจ้านายติ

## 4. กติกาที่ทุกขั้นต้องรักษา

### 4.1 ทุกขั้นเล่นได้ ทดสอบได้ commit แยก
แต่ละขั้นย่อยจบที่:
- `npm test` ผ่าน (ยกเว้น 2 ข้อของ `test/bounds.ts` ที่รู้กันอยู่)
- ผู้เล่นอัตโนมัติขอนแก่น 10 ปี (`PHAICITY_PLAY=1`) ไม่แย่ลงจนเล่นไม่ได้ เทียบตัวเลขก่อน/หลังลงในแถวของขั้นนั้น
- ลองในเกมจริงตามวิธีของสมุดภาพ (`docs/design/LOOK_BOOK.md`)
- รวมเข้า main

### 4.2 ผลเท่ากันทุกครั้ง (กฎออนไลน์ข้อ 1–5)
- ทุกการกระทำยังเป็นคำสั่งผ่าน `CityCommands`
- สุ่มด้วย `Random` เท่านั้น
- ภาพ 3D อ่านอย่างเดียว
- ระบบจำลองไม่แตะ DOM
- seed เดียวกัน + คำสั่งเดียวกัน ที่ก้าวเดียวกัน = เมืองเดียวกัน (`test/playthrough.ts`, `test/cityCore.ts`, `test/roadsStay.ts`)
- ขั้นที่เปลี่ยนกติกาจำลอง (1.3, 2, 3B, 4) จะเปลี่ยนผลของ seed เดิม:
  - ตั้งค่าที่ test คาดไว้ใหม่ใน commit เดียวกัน พร้อมเขียนเหตุผล
  - เพิ่ม `simVersion` ในเซฟ (ขั้น 0.3) ให้เซิร์ฟเวอร์รู้ว่าเมืองนี้เล่นด้วยกติการุ่นไหน

### 4.3 เลขสุ่มประจำตัว
วันนี้ `Random` ตัวเดียวถูกดึงตามลำดับสแกนช่อง ระบบใหม่จะทำแบบนี้:
- **ต้นเดือน:** ดึง `Random` หนึ่งครั้งเป็นเลขของเดือน
- **ของแต่ละชิ้น:** ได้เลขสุ่มจาก hash(เลขของเดือน, id ของมัน)
- **ผล:** เพิ่มหรือรื้ออาคารหนึ่งหลังไม่ทำให้การสุ่มของหลังอื่นเปลี่ยน replay ยังเท่าเดิม เพราะเลขของเดือนมาจาก `Random` ที่เซฟไว้
- **ฟังก์ชันเดียว:** `src/sim/agentRandom.ts` (ขั้น 0.2)

### 4.4 เซฟเก่าและแผนที่จังหวัดยังเปิดได้
- ทุกขั้นสร้างของใหม่จากช่องครั้งเดียวตอนโหลด แบบที่ `roadMigration.ts` และ `completeBuildings` ทำอยู่
- รูปแบบเซฟไม่เปลี่ยนจนขั้น 5 (v6)
- test เปิดเซฟ v4 และ v5 ทุกขั้น
- **ระบบใหม่เปิดเฉพาะแผนที่ขนาดจริง** (ช่องเล็กกว่า 40 ม., `CITY_TILE_MAX_M` ใน `src/units.ts` ตัวเดียวกับที่ใช้นับระยะเป็นเมตรอยู่แล้ว)
- แผนที่จังหวัด (ช่อง 110–1,030 ม.) และแผนที่ฝึก (10 ม.) ใช้ระบบช่องเดิม จนขั้น 5 ตัดสินว่าจะย้ายหรือเลิก (ข้อ 8)
- เหตุผล: เจ้านายให้ทำเมืองขอนแก่นให้ถึงระดับ Cities: Skylines ก่อนแผนที่อื่น

### 4.5 เร็วพอบนโน้ตบุ๊ก
วัดแล้ว 21 ต.ค. 2026 ด้วยสคริปต์อ่านอย่างเดียวบน `RoadGraph` จริง ถนนเป็นตารางทุก 120 ม. บนเครื่องนี้:

| กราฟ | จุดต่อ | เส้น | หาเส้นทาง A* หนึ่งเที่ยว | ต้นไม้ Dijkstra จากจุดเดียวทั้งเมือง |
|---|---|---|---|---|
| 2.3 กม. | 400 | 760 | 0.08 ms | 1 ms |
| 4.7 กม. | 1,600 | 3,120 | 0.24 ms | 3.4 ms |
| 7.7 กม. (กรอบเริ่ม) | 4,225 | 8,320 | 0.64 ms | 5.8 ms |

งบเวลาเดียวกันทุกขั้น:
- หน้าจอทำงานไม่เกิน 4 ms ต่อก้าว
- งานที่ใหญ่กว่านั้นไปทำใน Web Worker ตามแผนวาดเมตรข้อ 6
- ใน Node (test เซิร์ฟเวอร์ ผู้เล่นอัตโนมัติ) ทำในก้าวเดียวกันได้เลย

### 4.6 ผลจาก worker ต้องลงที่ก้าวเดิมทุกครั้ง
- ส่งงานไป worker ที่ก้าว k
- รับผลมาใช้ที่ก้าว k + 32 (ครึ่งเดือน)
- ถ้า worker ยังไม่เสร็จ หน้าจอรอ (หรือคิดเอง)
- ใน Node คิดทันทีแต่เก็บไว้ใช้ที่ k + 32 เหมือนกัน
- ผลจึงเท่ากันทุกเครื่อง

### ขั้น 1: จราจรเป็นรถจริงบนกราฟถนน (~6 รอบ) — **ทำก่อน**

**ทำไมก่อน:** เป็นช่องว่างใหญ่สุดเทียบกับ Cities: Skylines ที่เจ้านายเห็นทุกครั้งที่ดูเมือง และไม่ชนงานของไม้ไผ่28
(อาคาร) กับไม้ไผ่26 (ภาพพื้น)

**แบบ:**
```
ต้นทาง (บ้าน: คนวัยทำงาน, แปลงที่หาได้วันนี้จากช่อง จนขั้น 3B)
  │  เลือกปลายทางด้วยแรงดึงดูด ÷ เวลาเดินทาง (gravity model) ด้วยเลขสุ่มประจำตัว
  ▼
ปลายทาง (งาน: ร้าน โรงงาน นา อาคารบริการ; ช้อปปิ้ง: ร้าน; บริการ: โรงเรียน อนามัย)
  │  A* บนกราฟ (CSR) เวลาของเส้น = ยาว ÷ ความเร็ว × (1 + 0.15 (รถ/จุได้)^4)
  ▼
รถต่อเส้น (flow) → ความเร็วจริงต่อเส้น → เดือนหน้าเส้นทางเลี่ยงเส้นที่ติด
```

- **รวมการเดินทางเป็นกลุ่ม:** หนึ่งอาคารหนึ่งกลุ่มต่อปลายทาง ไม่ใช่ทีละคน
- **ตัวอย่างงบ:**
  - เมือง 20,000 คน ราว 3,000 อาคาร = ราว 3,000 เที่ยวต่อเดือน
  - ใช้เวลาราว 2 วินาทีบนกรอบเริ่ม ซึ่งเท่ากับหนึ่งเดือนที่ 3×
  - จึงต้องอยู่ใน worker
  - ถ้าเมืองใหญ่กว่านี้ สุ่มเลือกบางกลุ่มต่อเดือนและเฉลี่ยกับเดือนก่อน (หรือ Dijkstra ครั้งเดียวต่อจุดต้นทาง ใช้กับทุกปลายทาง)
- **ยังไม่ใช้ contraction hierarchies:** ต้องสร้างดัชนีใหม่ทุกครั้งที่ผู้เล่นวาดถนน ใช้เมื่อวัดแล้วช้าเท่านั้น
- **กฎใหม่ของการโต (แทนเดินสุ่ม 30 ช่อง):**
  - ไม่มีเส้นทางไปงานหรือร้านภายใน 20 นาที (ค่าเริ่มต้น ปรับได้ในกติกา) = ปัญหา "ไปไม่ถึง" เหมือน Cities: Skylines
  - แปลงโตช้าลงหรือถอยระดับ
  - เช็กลิสต์บอกเหตุผล (`plotWhy`)

| ขั้นย่อย | งาน | ผู้เล่นได้ |
|---|---|---|
| 1.1 | เลน ความเร็ว จุรถได้ ต่อระดับถนน (เพิ่มในตาราง `src/roadLevels.ts`: ลูกรัง 1 เลน 30 กม./ชม. … ทางด่วน 3+3 เลน 100 กม./ชม.) ค่าบำรุง = ความยาวในกราฟ × ระดับ (แทนนับช่อง) | ถนนเฉียงจ่ายค่าบำรุงเท่าถนนตรงยาวเท่ากัน |
| 1.2 | `src/sim/trips.ts`: สร้างการเดินทางต่อเดือนจากต้นทางและปลายทาง + หาเส้นทาง + รถต่อเส้น (`segmentFlow`, `segmentSpeed` ตาม id ของเส้น) **ไม่มี DOM รันใน Node** ทำงานคู่ระบบเก่า ยังไม่มีผลต่อการโต; test: ถนนตรงสองเส้นขนาน เส้นที่ใกล้กว่ารับรถก่อน พอติดรถเลี่ยงไปอีกเส้น | ยังไม่เห็น (วัดใน test) |
| 1.3 | **สลับ:** การโตอ่าน "ไปถึงไหม เวลาเท่าไร" จาก 1.2 แทน `makeTraffic`; บล็อก `trafficDensityMap` สร้างจากรถต่อเส้น (วาดลงช่องที่ถนนผ่าน) ผู้อ่านเดิมจึงทำงานต่อ (ช่องถนนรถติด ควันจากรถ คะแนนเมือง ความพอใจ ค่าผ่านทาง เฮลิคอปเตอร์ แผนที่) ; ตั้งค่า test ใหม่; ผู้เล่นอัตโนมัติ 10 ปีเทียบ | รถติดบนเส้นทางจริง เช่น ถนนเข้าตัวเมืองตอนเมืองโต; ร้านไกล 600 ม. ก็หาเจอ; บ้านที่ไปไหนไม่ได้บอกเหตุผล |
| 1.4 | `traffic-worker` (แบบเดียวกับ `city-road-worker`, ส่ง typed array ไม่คัดลอก) ตามข้อ 4.6 | เกมไม่กระตุกตอนต้นเดือนแม้เมืองใหญ่ |
| 1.5 | **รถ 3D ตามการเดินทางจริง** (`src/render3d/city/` แทน `CityRoadTraffic` ใน `pedestrians.ts`): instancing หนึ่ง mesh ต่อแบบรถ, รถเกิดจากเส้นทางของเดือน (ส่วนหนึ่งของกลุ่ม) วิ่งตามเส้นในกราฟ เลี้ยวที่แยกตามเส้นทาง เว้นระยะ ต่อคิวและช้าลงบนเส้นที่ติด จำนวนต่อเส้นตามรถจริง (ถนนว่าง = ไม่มีรถ) ใกล้กล้องสูงสุดราว 400 คัน ไกลเป็นจุดไฟ; รถเมล์วิ่งตามถนนจริงจากจุดที่วาง; รถไฟวิ่งตาม `railGraph` ด้วยโมเดลจริง แทนกล่องสีที่เลี้ยว 90° กลางช่อง | เห็นรถไปทำงานตอนเช้า กลับบ้านตอนเย็น ติดที่สี่แยกใจกลาง อัปเกรดถนนแล้วคิวหาย |
| 1.6 | ชั้นข้อมูลจราจรระบายสีตัวถนนตามรถ/จุได้ (เขียว→แดง) แทนสี่เหลี่ยม 32 ม.; การ์ดตรวจดูถนน: รถต่อชั่วโมง จุได้ ความเร็ว ใครใช้ถนนนี้ (บ้านไหนไปไหน) | รู้ว่าทำไมติดและแก้ตรงไหน |

**เซฟเก่าและแผนที่จังหวัด:**
- รถต่อเส้นไม่เซฟ คิดใหม่ในเดือนแรกหลังเปิด
- แผนที่จังหวัดใช้ `makeTraffic` เดิม (ข้อ 4.4)

**ความเสี่ยง:**
- สมดุลการโตเปลี่ยนแรงที่สุดในแผน เพราะวันนี้ "หาปลายทางไม่เจอ" ไม่มีผลเสีย
- ต้องทำหลังไม้ไผ่25 (การโต ผู้เล่นอัตโนมัติ) และไม้ไผ่24 (เงิน) รวมงานแล้ว หรือคุยกันก่อน 1.3
- ปล่อย 1.3 เปิดด้วยค่าที่ใจดี (เช่น 30 นาที) แล้วค่อยบีบ

### ขั้น 2: ไฟและน้ำไหลตามเส้นถนน (~2.5 รอบ)

| ขั้นย่อย | งาน | ผู้เล่นได้ |
|---|---|---|
| 2.1 | **ผูกอาคารกับเส้นถนน:** ทุกอาคาร (รายการ `gameMap.buildings`) และแปลง (จากช่อง จนขั้น 3B) รู้เส้นที่มันหันหน้าเข้าและระยะตามเส้น (`segment`, `along`, `side` ที่แผนวาดเมตรข้อ 4.2 วางไว้แล้วแต่ยังไม่ใช้) | ยังไม่เห็น |
| 2.2 | **ไฟ:** แบ่งเครือข่ายถนนเป็นกลุ่มที่ต่อกัน (union-find บนกราฟ); กำลังผลิตของกลุ่ม = โรงไฟฟ้าที่ติดเส้นในกลุ่ม; อาคารกินตามชนิดและระดับ (บ้านระดับ 1 น้อย ตึกสูงมาก) ไม่ใช่ช่องละ 1; ไฟไม่พอ: ไล่จ่ายจากใกล้โรงไฟฟ้าออกไปตามระยะบนถนน (Dijkstra หลายต้นทาง) ปลายสายดับก่อน; เลิกไฟวิ่งจากแปลงไปแปลง (`BLBNCNBIT`); เขียน `POWERBIT` ลงช่องให้ผู้อ่านเดิม | ไฟดับที่ปลายสายแบบเข้าใจได้; แปลงไม่ติดถนนไม่ได้ไฟจากเพื่อนบ้าน; ตึกสูงกินไฟจริง |
| 2.3 | **น้ำ:** แบบเดียวกัน ส่วนแบ่งตามคนและงานของอาคาร; ไม่พอ: แจกตามระยะจากโรงประปาบนถนน **ไม่ใช่ตามลำดับสแกน**; หอถังยังเป็นแหล่งของกลุ่ม | เลิก "ฝั่งตะวันออกแห้งก่อน"; บ้านไกลโรงประปาแห้งก่อน (เข้าใจได้ แก้ได้ด้วยโรงที่สอง) |
| 2.4 | ชั้นข้อมูลไฟ/น้ำระบายตามตัวถนนและอาคาร แทนช่อง | เห็นว่าถนนเส้นไหนมีน้ำ |

**เซฟเก่า:**
- สถานะไฟ/น้ำไม่เซฟอยู่แล้ว (คิดใหม่ทุกเดือน)
- `groundwater` ยังเป็นต่อช่องจนขั้น 4

**ความเร็ว:**
- union-find + Dijkstra หลายต้นทางบน 8,000 เส้น ไม่ถึง 10 ms ต่อเดือน
- ทำในหน้าจอได้ (วันนี้น้ำท่วมทุกช่องถนนทุกรอบ)

**ความเสี่ยง:** ไฟที่วิ่งข้ามแปลงหายไป เมืองเก่าที่พึ่งมันจะมีแปลงดับ ให้ผู้เล่นอัตโนมัติและเช็กลิสต์บอก "ไม่ติดถนน"

### ขั้น 3: อาคารกินที่ตามรูปฐานจริง (~7 รอบ)

**แบ่งงานกับไม้ไผ่28 (ห้ามทำซ้ำ):**
- ไม้ไผ่28 ทำโรงไฟฟ้าให้ระบบกินที่เท่าโมเดลแล้ว (3×3 หรือ 2×2 ตามยุค, `src/plantBlocks.ts`); โรงประปาคง 3×3 เพราะโมเดลกว้างเท่านั้น
- ต่อด้วยรูปฐานหมุนพร้อมรั้วที่เห็นได้
- แผนนี้ถือว่า **งานนั้นคือ 3A.0** และขั้น 3A ข้างล่างเริ่มหลังไม้ไผ่28 รวมเข้า main
- ถ้าไม้ไผ่28 ทำรูปฐานหมุนเป็นเมตร (ไม่ใช่บล็อกช่อง) ได้ถึงไหน 3A ตัดส่วนนั้นออก

**3A: อาคารของเจ้าเมือง (~2 รอบ)**

| ขั้นย่อย | งาน | ผู้เล่นได้ |
|---|---|---|
| 3A.1 | `PlacedBuilding` เพิ่ม `w, d` เมตร (ตามโมเดลจริงของยุค) + ดัชนีพื้นที่ (`rbush`, MIT, ต้องเพิ่มใน `package.json`); รูปฐาน = สี่เหลี่ยมหมุน | ยังไม่เห็น |
| 3A.2 | ตรวจชนด้วยรูป: รูปฐาน vs ตัวถนนจริง (เส้นในกราฟ × ความกว้างตามระดับ) vs รูปฐานอื่น vs ขอบที่ดิน; แทน `placeProblem` ทีละช่อง, `lotRects`, `aroundCorners`; กรอบแดง = รูปฐานจริง | **มุมหญ้าวางถนนได้**; อาคารหมุนแล้วไม่ยื่นทับถนนหรือโซน |
| 3A.3 | ช่องของอาคารคิดจากรูปฐาน (ทับ ≥ 50% ตามแผนวาดเมตรข้อ 4.4) ให้ผู้อ่านช่องเดิม; ระบบจำลองนับอาคารจากรายการ (ไม่หาจากช่องกลาง) | ไม่มีที่ว่างถูกจองลับ ๆ |
| 3A.4 | รถแมคโครและตรวจดูเลือก "ของใต้เมาส์" (อาคาร เส้นถนน แปลง) กรอบตามรูปของมัน | ไม่เห็นกรอบสี่เหลี่ยม 16 ม. |

**3B: แปลงเป็นอาคารทีละหลัง (~4 รอบ) — การเปลี่ยนระบบจำลองใหญ่สุด**

| ขั้นย่อย | งาน | ผู้เล่นได้ |
|---|---|---|
| 3B.1 | **แปลงจากช่องย่อย:** ช่องย่อยที่ทาชนิดเดียวกันติดกันตามเส้นถนนเดียวกัน = แปลง (กว้างหน้า 4–48 ม. × ลึก 4–16 ม.) แทน "ช่อง 16 ม. ที่ทาถึง 28%"; ตึกแถวหนึ่งคูหา (4 ม.) บ้าน 12 ม. ที่ 3.3 ทำในภาพแล้วกลายเป็นของจริงในระบบ | ทาแถวเดียวก็มีตึกขึ้น; ตึกขึ้นตรงที่ทาเป๊ะ |
| 3B.2 | **รายการอาคารที่โต** (id คงที่, รูปฐาน, ชนิด ระดับ ยุค วันสร้าง) เป็นตัวจริงแทนค่าช่อง; คน/งาน = พื้นที่ชั้น × ความหนาแน่นตามระดับ (บ้าน 12 ม. ระดับ 1 ราว 4 คน, คอนโดราว 200 คน) แทนก้อน 20 คนต่อระดับ; แปลงรวมเกิดจากแปลงติดกันตามถนน ไม่ใช่ช่องเลขคู่ (`lotOf`) | คนเพิ่มเป็นขั้นเล็ก ๆ; ตึกไม่เสียวันสร้างเมื่อรวมแปลง |
| 3B.3 | การโตเดินตามรายการ (ไม่ใช่สแกนช่อง) ด้วยเลขสุ่มประจำตัว; ช่องของแปลงสร้างจากรายการให้ผู้อ่านเดิม (ไฟ น้ำ ทำผ่านขั้น 2 แล้ว) | เมืองเดิมโตเหมือนเดิมในภาพรวม (ผู้เล่นอัตโนมัติเทียบ) |
| 3B.4 | เซฟเก่า: แปลงจากช่องเดิมเป็นรายการครั้งเดียว (ระดับ ชนิด ยุค) | เมืองเก่าเปิดแล้วตึกเดิมอยู่ครบ |

**3C: นาเป็นรูปที่ทา (~1 รอบ)**
- นา ไร่ สวน บ่อปลา ทาเป็นช่องย่อยแบบโซน รูปตามที่ทา คันนาตามขอบที่ทา (`farmFields.ts`)
- ทางเกวียนเป็นเส้นสั้นในกราฟ ไม่ใช่ BFS ทีละช่อง

**ความเสี่ยง:**
- 3B แตะทุกระบบที่อ่านแปลง: เช็กลิสต์ คะแนนยุค ภาพ 3D `frontage.ts` ผู้เล่นอัตโนมัติ
- ต้องเป็นงานเดียวต่อเนื่อง ไม่แตกให้หลายตัวทำพร้อมกัน
- ภาพ 3D ของแปลงต้องอ่านรายการแทนช่อง (`TileSnapshot.placement` ต่อเลขช่อง)

### ขั้น 4: ค่ารอบ ๆ เป็นระยะจริง (~3.5 รอบ)

**แบบ:**
- ทุกอย่างที่ปล่อยหรือให้ค่าเป็น "แหล่ง" ที่มีตำแหน่งเมตรและแรง:
  - อาคาร โรงงาน เหมือง นา จุดหรือรูป
  - ถนน เป็นเส้น แรงตามรถจากขั้น 1
- ค่าที่อาคารแต่ละหลัง = ผลรวมของแหล่งรอบ ๆ ที่ลดตามระยะเมตร (เช่น ควันลดครึ่งทุก 150 ม.) และลมพาควันไปตามทิศ (`src/wind.ts`)
- หาแหล่งใกล้ด้วยดัชนีพื้นที่
- **ตัวอย่างงบ:**
  - 3,000 อาคาร × แหล่งในรัศมีราว 200 ตัว = 0.6 ล้านครั้ง
  - ราว 10–20 ms ต่อเดือน
  - แบ่งทำหลายก้าวได้

| ขั้นย่อย | งาน | ผู้เล่นได้ |
|---|---|---|
| 4.1 | ควัน เสียง (จากรถ จากโรงงาน เหมือง นา ขยะ) เป็นแหล่ง + ลม; แทน `pollutionDensityMap` บล็อก 32 ม. + พิษเหมือง/หมอกควันต่อช่อง | ควันลอยตามลม ไม่มีขอบ 32 ม. |
| 4.2 | ราคาที่ดิน: ระยะจากใจกลางเป็นเส้นตรง (ไม่ใช่แมนฮัตตัน 48 ม.) + ควัน + อาชญากรรม + บริการ + ธรรมชาติ น้ำ จวน คลอง เทศกาล รถไฟฟ้า แต่ละอย่างมีรัศมีเมตร; แทนบล็อก 2×2 ที่วัดที่มุมบนซ้าย | ราคาที่ดินไล่สีนุ่ม; ย่านเฉียงจากใจกลางไม่เสียเปรียบ |

## 8. ที่เจ้านายต้องตัดสิน (ระหว่างทาง)

1. **กฎ "ไปไม่ถึง" ของขั้น 1.3:**
   - เวลาเดินทางสูงสุดที่ยังนับว่าไปถึง
   - เสนอ: เริ่ม 30 นาทีให้ใจดี แล้วค่อยบีบเป็น 20
2. **แผนที่จังหวัดและแผนที่ฝึก (ขั้น 5.6):**
   - ย้ายมาระบบใหม่ หรือเลิกระบบช่องเดิม
   - เสนอ: ตัดสินเมื่อขอนแก่นถึงขั้น 4 แล้ว
3. **รถ 3D สูงสุดกี่คันใกล้กล้อง:**
   - เสนอ 400 คัน
   - ปรับตามระดับภาพ ต่ำ/กลาง/สูง
4. **ไฟวิ่งข้ามแปลงที่ไม่ติดถนน (ขั้น 2.2):**
   - เลิก (เสนอ เพราะตรงกับ "ทุกอย่างต้องติดถนน")
   - หรือเก็บไว้
5. **ความหนาแน่นคนต่อพื้นที่ชั้นแต่ละระดับ (ขั้น 3B.2):** ตัวเลขเริ่มต้นจะลงในกติกา (`data/province-rules.json`) ให้เจ้านายแก้ได้
