# แผนเกมใหม่: ขอนแก่นให้เล่นได้ถึงที่สุด

**ร่างแรก 13 ต.ค. 2026 ยังรอเจ้าของดูและแก้** ยังไม่มีงานไหนในแผนนี้เริ่มเขียนโค้ด

ข้อมูลตั้งต้นของแผนนี้:
- `docs/INSPECTOR.md`: วัตถุของแต่ละเครื่องมือมีข้อมูลอะไรอยู่แล้ว ร่างคลาส และความพอใจของแต่ละชนิด
- `docs/3d/MODEL_CATALOG.md`: โมเดล 3D แต่ละตัวมีอะไร และยังขาดอะไร

## 1. เป้าหมาย

ทำ **จังหวัดขอนแก่นจังหวัดเดียวให้เล่นได้ครบและลึกที่สุดก่อน** แล้วใช้เป็นแม่แบบของอีก 76 จังหวัด

- **ครบทุกชั้น:** ข้อมูลแผนที่ การจำลอง ภาพ 3D หน้าจอ และเสียง
- **เล่นได้ยาว:** จากหมู่บ้านจนเป็นเมืองใหญ่ ยศหมื่นถึงเจ้าพระยา โดยไม่มีบั๊กและสมดุลดี
- **ลื่นบนโน้ตบุ๊กการ์ดจอออนบอร์ด** และ server คำนวณเมืองซ้ำได้ผลเดิมทุกครั้ง (แผนออนไลน์)

## 2. สิ่งที่เจ้าของตัดสินใจแล้ว (13 ต.ค. 2026)

1. **ทุกวัตถุเป็นคลาส:** "แต่ละ object ต้องเป็นลักษณะ class" คลิกอะไรก็เห็นรายละเอียดของสิ่งนั้น
2. **ความพอใจ:** "ทุกอย่างแล้วสรุปพอใจ หรือไม่พอใจที่จะอยู่ ... ในแต่ละ object มันจะแตกต่างกันออกไป"
   - บ้าน: คนพอใจจะอยู่ไหม
   - ร้าน โรงงาน โรงแรม: เจ้าของพอใจกับกิจการไหม
   - บริการ เช่น โรงเรียน โรงไฟฟ้า: ทำงานได้ดีไหม
3. **จำลองรายคนแบบ Cities: Skylines:** คนมีบ้าน ที่ทำงาน อายุ และเดินทางจริง
4. **ความพอใจแทนกติกาการโตเดิมของ micropolis:** เป็นตัวตัดสินว่าอาคารโต ทรุด คนย้ายออก หรือปิดกิจการ
5. **แผนครอบคลุมทั้งเกม:** จัดรายการงานทั้งหมดใหม่รอบเรื่องนี้
6. **ทรัพยากรสร้างเอง ไม่ใช้ข้อมูลแร่จริง:** "ไม่ต้องไปเช็คเพราะเราคือเกม" สร้างจากภูมิประเทศจริงที่มีอยู่แล้ว
7. **ขอนแก่นก่อน:** "เราจะต้องทำจังหวัดขอนแก่น ให้เล่นได้ ถึงที่สุดก่อน"
8. **เมืองใหญ่สุดราว 1 แสนคน:** เท่าเทศบาลนครขอนแก่นจริง พอดีกับแผนที่เมือง 6.4 × 6.4 กม.
   จำลองเป็นครัวเรือนราว 3–4 หมื่นหลัง
9. **ครัวเรือนมีชื่อ:** คลิกบ้านเห็นครอบครัว เช่น "ครอบครัวศรีสุข 4 คน" แต่ละคนมีชื่อ อายุ และงานหรือโรงเรียน
   คลิกคนเดินแล้วเห็นว่ามาจากบ้านไหนและกำลังไปไหน ชื่อสร้างจาก seed จึงเก็บในเซฟได้โดยไม่เปลือง
10. **ภัยจริงกับโหมดแฟนตาซี:** เล่นปกติมีแต่ภัยที่เกิดจริงในขอนแก่นตามฤดู (น้ำท่วม ภัยแล้ง ไฟไหม้ พายุฤดูฝน
    อุบัติเหตุ) ภัยมีผลต่อความพอใจและเตรียมรับมือได้ (หอเตือนภัย คันกั้นน้ำ) ส่วนสัตว์ประหลาดกับภัยเกินจริงของ
    micropolis เก็บไว้ให้ผู้เล่นกดเรียกเองในโหมดแฟนตาซี
11. **การจำลองกับภาพทำคู่ขนาน:** Claude Code ทำ core และการจำลองตามเฟส 0–7 ส่วนผู้ช่วยทำโมเดลของเฟส 8
    (อาคารที่ยังเป็นกล่องก่อน) ใน worktree ของตัวเอง ตอนโควตาเหลือเยอะ แล้ว Claude Code ตรวจก่อนรวม
12. **สองฝั่งของเมือง:** "แบ่งแยก ในส่วนของ ชุมชนกับ service ของส่วนกลาง"
    - **ชุมชน** (`CommunityBuilding`): บ้าน ร้าน โรงงาน (และโรงแรม) เอกชนเป็นเจ้าของ โตเอง จ่ายภาษี
      ความพอใจคือคนหรือเจ้าของพอใจจะอยู่ไหม
    - **บริการส่วนกลาง** (`CentralService`): ไฟ น้ำ ขยะ โรงเรียน โรงพยาบาล ตำรวจ ดับเพลิง ขนส่ง ที่ว่าการ
      เจ้าเมืองสร้างและจ่ายค่าบำรุง ความพอใจคือให้บริการได้ดีแค่ไหน (งบ คน ภาระ ระยะ)
13. **ไร่นา ท่าประมง และเหมือง แบบผสม:** ไร่นากับท่าประมงเป็นของชุมชน (เจ้าเมืองกำหนดที่ให้ ชาวบ้านทำเอง โตเอง
    จ่ายภาษี) ส่วนเหมืองเป็นสัมปทานของส่วนกลาง (เจ้าเมืองให้สัมปทาน ได้ค่าภาคหลวง และรับผิดชอบมลพิษ)
    ตอนนี้รายได้ไร่นาและประมงยังเข้าคลังแบบเดิม จะเปลี่ยนเป็นภาษีในเฟส 7
14. **ทุกวัตถุมีคน:** แต่ละวัตถุบอกได้ว่ามีใครเกี่ยวข้องและเท่าไหร่ เทียบกับที่รับได้
    - บ้าน: คนอยู่ (ครัวเรือนและสมาชิก)
    - ร้าน โรงงาน โรงแรม ไร่ ท่าประมง: คนงาน และลูกค้า แขก หรือผลผลิต
    - บริการส่วนกลาง: เจ้าหน้าที่ และคนที่มาใช้ (นักเรียน คนไข้ ผู้โดยสาร) เทียบกับที่นั่งหรือที่รับได้
    - ก่อนเฟส 7 เป็นตัวเลขประมาณจากสูตรเดิมของเกม ตั้งแต่เฟส 7 เป็นคนจริงจากครัวเรือน
15. **ยานพาหนะของสถานที่ (fleet):** "โรงขยะมีรถได้กี่คัน จะซื้อเพิ่มได้ โรงพยาบาลมีรถพยาบาลกี่คัน"
    - บริการส่วนกลางแต่ละแห่งมีรถของตัวเอง เริ่มต้นจำนวนหนึ่ง และซื้อเพิ่มได้ไม่เกินเพดานตามระดับอาคาร
      - ขยะ: รถเก็บขยะ
      - โรงพยาบาล: รถพยาบาล
      - ดับเพลิง: รถดับเพลิง
      - ตำรวจ: รถสายตรวจ
      - ขนส่ง: รถเมล์และสองแถว
      - ประปา: รถน้ำแจกน้ำหน้าแล้ง
    - ของชุมชนก็มี เช่น เรือประมงของท่าประมง รถไถของไร่ แต่เจ้าของซื้อเอง ไม่ใช่เจ้าเมือง
    - **รถแต่ละคันเป็น object ของตัวเอง** (เจ้าของ 13 ต.ค. 2026: "อันนี้ คือ object นะ"): คลาส `Vehicle` แตกจาก
      `CityObject` (ไม่ใช่ `Building`) แล้วแตกต่อเป็นรถแต่ละชนิด เช่น `GarbageTruck`, `Ambulance`, `FireEngine`,
      `PoliceCar`, `Bus`, `Songthaew`, `WaterTanker`, `FishingBoat`, `Tractor`
      - มีของตัวเอง: สังกัดสถานที่ไหน ชนิด อายุ สภาพ คนขับ งานที่กำลังทำ (จอดที่ฐาน ออกงาน ขากลับ) ของที่บรรทุก
        (ขยะกี่ตัน คนไข้ ผู้โดยสาร) และตำแหน่ง
      - คลิกรถที่วิ่งอยู่แล้วเห็นการ์ดของมัน เช่น "รถเก็บขยะคันที่ 3 ของบ่อฝังกลบหนองแวง บรรทุก 6/8 ตัน กำลังกลับฐาน"
      - เก่าแล้วเสียบ่อย ค่าซ่อมขึ้น ต้องซื้อใหม่แทน
      - รถส่วนตัวของครัวเรือน (รถยนต์ มอเตอร์ไซค์) เป็น `Vehicle` เหมือนกัน และมาพร้อมผู้คนในเฟส 7
16. **ภูมิทัศน์ขอนแก่นตาม GIS จากฐานข้อมูลของเรา:** สร้างแผนที่จาก PostGIS ในเครื่อง (`docs/geo/THAILAND_DB.md`)
    แบบอบล่วงหน้าเป็นไฟล์แผนที่ (เบราว์เซอร์ต่อฐานข้อมูลตรงไม่ได้ เกมต้องเล่นออฟไลน์ได้ และ server ต้องได้แผนที่เดียวกัน)
    ภายหลัง server ที่มี PostGIS ใช้สคริปต์เดียวกันสร้างแผนที่จังหวัดอื่นได้
17. **ถนนและทางรถไฟจริงจาก GIS** (เจ้าของ 13 ต.ค. 2026: "ทางและทางรถไฟ ก็ใช้ได้จาก gis" แทนกติกาเดิมของ 12 ต.ค.
    ที่ให้มีแค่ทางรถไฟกับถนนลูกรังไปจังหวัดข้างเคียง) ระดับถนนตามชนิดและจำนวนช่องจราจรใน OSM และใช้ชื่อถนนจริงจาก OSM
    แทนชื่อที่เกมตั้งเอง ถ้าเส้นไหนไม่มีชื่อ ค่อยใช้ชื่อที่เกมตั้ง
18. **นาข้าวให้เกมเดาเอง:** OSM วาดนาไว้แค่ราว 88 ตร.กม. ในขอนแก่น ที่ราบที่ไม่มีอะไรอยู่ ไม่ใช่ป่า ไม่ใช่น้ำ
    และไม่ไกลน้ำหรือคลองชลประทาน ให้เป็นนา (ไม่เพิ่มแหล่งข้อมูลใหม่)
    - รถแต่ละคันมีค่าซื้อ ค่าบำรุงรายเดือน และต้องมีคนขับ (เจ้าหน้าที่ ข้อ 14) ตามหลัก "มีได้ก็ต้องมีเสีย"
    - ผล: รถพอหรือไม่พอกำหนดว่าบริการไปถึงได้ไกลและเร็วแค่ไหน (ขยะเก็บทันไหม รถพยาบาลมาทันไหม) และรถวิ่งบนถนนจริง
      จึงติดไฟแดงหรือรถติดได้
    - การซื้อหรือขายรถเป็น command ผ่าน `CityCommands` และจำนวนรถบันทึกกับวัตถุในเซฟ
    - ทำตามเฟส: ข้อมูลกับปุ่มซื้อในการ์ด (เฟส 7 ข้อ 1 และ 4) → ผลต่อบริการและการเดินทาง (เฟส 7 ข้อ 3–5) → เห็นรถแต่ละแบบวิ่งใน 3D (เฟส 8)
      ตอนนี้มีโมเดลรถบรรทุก กระบะ รถเมล์ และสองแถวแล้ว แต่ยังขาดรถขยะ รถพยาบาล รถดับเพลิง และรถตำรวจ

## 3. หลักที่ทุกเฟสต้องรักษา

- **เกมเล่นได้ทุกเฟส:** แต่ละเฟสจบด้วยเกมที่เล่นได้และ commit ได้ ไม่รื้อจนพังกลางทาง
  ของใหม่เปิดทีละส่วน ส่วนของเดิมยังทำงานจนของใหม่พร้อมแทน
- **การจำลองไม่มี DOM** ใช้ `Random` ตัวเดียว และผู้เล่นเปลี่ยนเมืองผ่าน command เท่านั้น (กฎใน `CLAUDE.md`)
- **ตัววาดอ่านอย่างเดียว:** ตัววาด 3D การ์ด และแผนที่ อ่านจากคลาส ไม่เขียนกลับ
- **เซฟเก่ายังเปิดได้:** มี migration ใน `transitionOldSave` ทุกครั้งที่รูปแบบเซฟเปลี่ยน
- **วัดความเร็วทุกเฟส:** เมืองทดสอบขอนแก่นขนาดเป้าหมายต้องได้เวลาต่อรอบการจำลองและเฟรมเรตตามงบ (ข้อ 6)

## 4. เฟส

ตกลงกับเจ้าของ 13 ต.ค. 2026: core กับภูมิทัศน์ขอนแก่นเดินคู่กัน ส่วนผู้ช่วยทำโมเดลคู่ขนานไปตลอด (ข้อ 11)
แต่ละเฟสจบด้วยเกมที่เล่นได้

### เฟส 0: Core (`docs/CORE_DESIGN.md`)
- ทำแล้ว (13 ต.ค. 2026):
  - วัตถุเป็นคลาส แยกฝั่งชุมชนกับส่วนกลาง (`src/objects/`)
  - `CityCore` เมืองที่ไม่มีหน้าจอ (`src/core/`) เกมสร้างเมืองผ่าน core แล้ว คำสั่งถูกบันทึก
  - แผนที่จริงออกมาเหมือนเดิมทุกครั้ง ทำให้เมืองรันซ้ำได้ผลเดิม
  - วัดความเร็วแผนที่เมืองขอนแก่น
- เหลือ:
  - ย้ายการขยับ sprite เข้า step
  - events ของ core
  - ตัวเล่นอัตโนมัติหลายปีพร้อมเช็กสมดุล
- **ผู้เล่นเห็น:** เกมเหมือนเดิม แต่โครงพร้อมรับทุกอย่าง

### เฟส 1: สร้างแผนที่ขอนแก่นจาก PostGIS (ข้อ 16–17)
- สคริปต์สร้างแผนที่อ่านฐานข้อมูล PostGIS ในเครื่องแทนไฟล์ cache ที่ดาวน์โหลดไว้
- ทำภาพเทียบของจริงกับแผนที่ในเกม และรายงานว่า OSM ขาดตรงไหน
- ถนนและทางรถไฟจริง: ระดับถนนตามชนิดและจำนวนช่องจราจร และชื่อถนนจริง
- **ผู้เล่นเห็น:** ถนนจริงของขอนแก่นพร้อมชื่อ

### เฟส 2: ภูมิประเทศ
- ความสูงพื้นละเอียดขึ้น (ชุด 30 ม. ต้องให้เจ้าของอนุมัติแหล่งข้อมูลก่อน)
- เส้นชั้นความสูง และความชันมีผลกับการสร้าง
- **ผู้เล่นเห็น:** เทือกเขาภูเวียง ที่ราบลุ่มน้ำชี

### เฟส 3: น้ำ
- แม่น้ำกว้างตามจริง (พอง ชี) อ่างอุบลรัตน์ บึงแก่นนคร บึงทุ่งสร้าง คลองชลประทาน พื้นที่ชุ่มน้ำ
- ที่ลุ่มที่น้ำท่วมถึง
- **ผู้เล่นเห็น:** น้ำท่วมตรงที่ท่วมจริง

### เฟส 4: พื้นที่
- นาข้าวที่เกมเดาเอง (ข้อ 18) มีคันนา
- ป่าแต่ละแบบ (ตรวจแปลงที่วาดกว้างเกินจริง) สวน ทุ่งหญ้า
- หมู่บ้านเดิม 1,466 แห่งเป็นจุดตั้งต้นของชุมชน
- **ผู้เล่นเห็น:** ดูออกว่าเป็นขอนแก่น

### เฟส 5: ทรัพยากรรายช่อง
- แร่ ดิน ลม ปลา แดด สร้างจากภูมิประเทศจริงของเฟส 2–4 ตามระดับของจังหวัด
- ระบายสีบนพื้น 3D ลูกศรลม ควันลอยตามลม
- ทำเลมีผล: เหมืองขุดแร่ใต้ตัวจริง ไร่ขึ้นกับดิน กังหันขึ้นกับลมตรงจุดนั้น
- **ผู้เล่นเห็น:** ต้องเลือกทำเลจากทรัพยากร

### เฟส 6: สองระดับ
- แผนที่จังหวัดขอนแก่นแบบหยาบเชื่อมกับแผนที่ 26 อำเภอ

- **ผู้เล่นเห็น:** เล่นได้ทั้งจังหวัด

### เฟส 7: ผู้คนและความพอใจ
ดึงระบบเดิมออกจาก simulation ทีละตัว (`docs/CORE_DESIGN.md` หัวข้อ 6) แล้วทำตามลำดับนี้
1. **การ์ดคลิกดู:** แท็บ ภาพรวม / คน / เงิน / รถ ไอคอนปัญหาเหนืออาคาร และแก้ตัวตรวจเดิมที่อ่านไทล์ใหม่ผิด
   (`docs/INSPECTOR.md`)
2. **ความพอใจ (แสดงอย่างเดียว):** คะแนนพร้อมปัจจัย ชั้นแผนที่ความพอใจ ไว้ปรับน้ำหนักก่อน
3. **ผู้คน:** ครัวเรือนมีชื่อ อายุ งาน โรงเรียน การเดินทางตามถนนและขนส่ง Web Worker
4. **รถเป็นวัตถุ:** สถานที่ซื้อรถเพิ่มได้ สายรถเมล์และสองแถวที่ผู้เล่นลากเอง
5. **ความพอใจคุมเมือง:** แทนการโตเดิม นโยบายแถบเลื่อน น้ำท่วม ปลูกป่า
6. **เศรษฐกิจรายอาคาร:** ร้าน โรงงาน โรงแรม ภาษีรายอาคาร กราฟ 12 เดือน
- **ผู้เล่นเห็น:** เมืองมีชีวิต โตหรือทรุดด้วยเหตุผลที่อธิบายได้

## 10. เจ้าเมืองจัดการอะไรได้บ้าง

เจ้าของ 13 ต.ค. 2026: "ในเจ้าเมืองเองจะจัดอะไรได้บ้าง คิดด้วยนะ" และ "ภาษีหรือ service ต่างๆ มันมีรายละเอียดปลีกย่อยเยอะ"

**หลัก:**
- ทุกอำนาจของเจ้าเมืองเป็น command (`src/cityCommands.ts`) และทุกค่าที่ตั้งได้เป็นข้อมูลในตาราง ไม่เขียนตัวเลขลงโค้ด
- **มีได้ก็ต้องมีเสีย:** ทุกอย่างมีผลต่อเงิน ความพอใจ และวัตถุที่เกี่ยวข้อง
- **ไม่ยุ่งการเมืองจริง:** ไม่มีพรรค การเลือกตั้ง หรือสถาบัน เจ้าเมืองเป็นผู้บริหารที่ได้ยศจากผลงาน

### 10.1 เจ้าเมืองเป็นวัตถุ (`Ruler`)
- ยศ (หมื่นถึงเจ้าพระยา มีแล้ว)
- **ศรัทธา:** ความพอใจเฉลี่ยของครัวเรือนรวมกับผลงาน การเลื่อนยศใช้ทั้งขนาดเมืองและศรัทธา
- ที่ว่าการ ส่วนต่อเติม และนโยบายที่เปิดอยู่ (มีแล้ว)
- **คณะทำงาน:** หัวหน้าส่วนช่าง คลัง สาธารณสุข การศึกษา ปลัด แต่งตั้งได้ตามยศและส่วนต่อเติม
  แต่ละคนช่วยงานด้านตัวเอง เช่น หัวหน้าคลังเก็บภาษีได้ครบขึ้น
- **บันทึกการตัดสินใจ:** ย้อนดูได้ว่าตั้งอะไรเมื่อไหร่ แล้วเกิดอะไรตามมา

### 10.4 บริการแต่ละอย่างตั้งอะไรได้

**ทุกบริการมีชุดเดียวกันจาก `CentralService`:**
- งบ (%) คน (เจ้าหน้าที่) รถ (ข้อ 15) เวลาเปิด ค่าบริการ ที่รับได้ คุณภาพ รัศมี และค่าบำรุง
- ความพอใจของบริการมาจากสิ่งเหล่านี้

**แต่ละอย่างมีรายละเอียดของตัวเอง:**

| บริการ | รายละเอียดเฉพาะ |
|---|---|
| โรงเรียน | ที่นั่ง ครูต่อนักเรียน งบรายหัว อาหารกลางวัน รถรับส่ง เรียนฟรีหรือเก็บค่าเทอม คุณภาพการสอน → ระดับการศึกษาของครัวเรือน → งานที่ทำได้ |
| โรงพยาบาล รพ.สต. | เตียง หมอ พยาบาล รถพยาบาล คิวรอ ค่ารักษาหรือรักษาฟรี โรคตามฤดู (ไข้เลือดออกหน้าฝน) |
| ขยะ | รถ รอบเก็บ (ทุกวันหรือวันเว้นวัน) คัดแยก ค่าเก็บ บ่อเต็ม ขายของรีไซเคิล |
| ประปา | กำลังผลิต คุณภาพน้ำ น้ำสูญเสียจากท่อรั่ว แรงดัน ค่าน้ำขั้นบันได รถน้ำหน้าแล้ง |
| ไฟฟ้า | กำลังผลิต สายส่ง ไฟดับ ค่าไฟ เชื้อเพลิง (มีบางส่วน) |
| ตำรวจ | สายตรวจ รถ ด่าน กล้องวงจรปิด ความปลอดภัยกลางคืน |
| ดับเพลิง | รถ หัวดับเพลิง เวลาไปถึง ฝึกซ้อม |
| ขนส่งสาธารณะ | สาย ความถี่ ค่าโดยสาร รถ ป้าย |
| ถนน | ซ่อมหลุมบ่อ ไฟถนน ไฟจราจร ค่าจอด ห้ามรถบรรทุกบางเวลา |
| สวนและนันทนาการ | ดูแลความสะอาด กิจกรรม เวลาเปิด |

**วิธีเก็บในโค้ด:** ตาราง `*_SPECS` ของแต่ละบริการขยายเป็นค่าตั้งต้น ส่วนค่าที่เจ้าเมืองตั้งเก็บในวัตถุ (บันทึกลงเซฟ)
เปลี่ยนค่าด้วย command เช่น `{ type: "service", id, setting: "collection", value: "daily" }`

**ทำทีละชั้น ไม่ให้ผู้เล่นจมกับรายละเอียด:**
1. เริ่มเล่น: เห็นแค่ งบ (%) กับค่าบริการ ค่าอื่นใช้ค่าตั้งต้นที่สมเหตุสมผล
2. เมื่อยศสูงขึ้นหรือมีส่วนต่อเติมที่ว่าการ (เช่น หน่วยคลัง หน่วยวางแผน) ค่าละเอียดเปิดเพิ่ม
3. การ์ดแสดงผลของทุกค่าก่อนเปลี่ยน ตามหลัก UX ในหัวข้อ 9
