# แผนเปลี่ยนเป็นวาดแบบเมตร (ถนน → อาคาร → โซน) และเทคโนโลยีใหม่

เจ้าของโปรเจกต์ 20 ต.ค. 2026: "การวาดเป็นช่องๆ แบบนี้ มันคุมแต่ละ object ยาก ... เขียนแผนการเปลี่ยนเป็นวาดแบบเมตร
(ถนน → อาคาร → โซน) ลง docs ก่อน แล้วค่อยลงมือทีละขั้น" และ "อยากให้เกมส์ทันสมัยที่สุด ... ต้องได้ 4 ดาวอย่างต่ำ"

เอกสารนี้คือแผนและการตัดสินใจ สถานะว่าทำถึงไหนอยู่ในตาราง "ความคืบหน้า" ท้ายไฟล์

---

## 1. ทำไมต้องเปลี่ยน

วันนี้ของหนึ่งชิ้นถูกเก็บหลายแบบ แล้วแปลงไปมาทุกครั้งที่อะไรเปลี่ยน ของจึง "ขยับเอง":

| ของ | เก็บอย่างไรตอนนี้ | ปัญหาที่เจอจริง |
|---|---|---|
| ถนน | ช่อง (ค่า 64–206 บนแผนที่ ช่องละ 16 ม.) + `roadPieces` + `roadPaths` (ช่องที่ลากผ่าน + จุดคุมเป็นช่องมีเศษ) แล้วคิดเส้นโค้งใหม่จากช่องทุกครั้ง (`networkOf` → `roadLines`) | คลิกต้องปัดเป็นช่องก่อน แล้วถูกดูดเข้าถนนใกล้ ๆ (ถนนไปลงที่อื่น), เส้นที่วาดได้ขั้นบันไดของช่อง, ไม่มีที่เก็บจุดต่อ/เส้นถนนเป็นเมตรเลย |
| อาคาร | ช่อง 3×3 ตั้งตรงกับแผนที่ (`buildBuilding`) + ท่าที่วาด `buildingPoses` [x, z, หมุน] แยกกัน | ช่องที่จองกับตัวที่วาดเลือกคนละที่ (`buildingTile` หาช่องว่าง ±3 ช่อง), ที่ดินหมุนตามถนนแต่ช่องตั้งตรง มุมช่องจึงโผล่ชนถนน (`aroundCorners`, `lotRects`) |
| โซน | ช่องย่อย 4 ม. วางตามเส้นถนนที่คิดจากช่อง (`zoneCells.ts`) คีย์เป็นตำแหน่งบนตาราง 1 ม. | ถนนเปลี่ยนนิดเดียว ช่องย่อยทั้งแถวคิดใหม่, ตอนวางถนนลบช่องย่อยด้วยสูตรคีย์ผิด (`cityCommands.ts` ใช้ 4×4 ต่อช่อง แต่คีย์จริงเป็นตาราง 1 ม.) |

simulation (ไฟ น้ำ จราจร การโตของแปลง) อ่านช่องทั้งหมด และทำงานดีอยู่แล้ว ไม่ใช่ตัวปัญหา

## 2. เป้าหมาย

**ของที่ผู้เล่นวาดเป็นตัวจริง เก็บเป็นเมตร ส่วนช่องบนแผนที่ "สร้างจาก" ของเหล่านั้นให้ simulation ใช้**

- วาดตรงไหนได้ตรงนั้น: ภาพตัวอย่างก่อนคลิก = สิ่งที่ได้หลังคลิก ทุกเมตร
- ของที่วาดแล้วไม่ขยับเอง เว้นแต่ผู้เล่นสั่งย้าย (กฎเดิมของเจ้าของ: "สิ่งก่อสร้างที่วาดแล้วห้ามขยับอีก")
- simulation อ่านช่องเหมือนเดิม จึงไม่ต้องเขียน simulation ใหม่ในแผนนี้
- ยังเป็นคำสั่งที่ส่งต่อได้ (`applyCommand`), ผลเหมือนเดิมทุกครั้งเมื่อ seed และคำสั่งเหมือนกัน (กฎ online plan ข้อ 1–5)

## 3. หลักที่ใช้ทุกขั้น

1. **เมตรคือหน่วยจริง** โมดูลเดียว `src/units.ts` แปลง เมตร ↔ ช่อง ↔ หน่วย 3D (วันนี้กระจายอยู่ ~10 ที่, มี `/10` ฝังในโค้ดโซน)
2. **ดูดเข้าเฉพาะสิ่งที่เห็นบนจอ** ระยะดูดวัดเป็นพิกเซล (ประมาณ 12–16 px) แสดงจุดที่จะลงก่อนคลิก กด Shift ค้าง = ไม่ดูดเลย
3. **ดูดเข้าได้ 4 แบบเท่านั้น** จุดต่อถนน, ปลายถนน, เส้นถนน (จุดตั้งฉาก), มุม 15°/45°/90° กับถนนเดิม ไม่มีการย้ายจุดไปที่ช่องอื่น
4. **ทุกอย่าง undo ได้ทั้งชิ้น** undo เก็บ "ก่อน/หลัง" ของกราฟถนน อาคาร โซน (วันนี้ undo เก็บแค่ค่าช่อง ถนนจึงคืนไม่ครบ)
5. **ช่องคิดจากของแบบแน่นอน** ฟังก์ชันเดียวต่อชนิด ผลเหมือนเดิมทุกครั้ง ไม่สุ่ม เพื่อให้ replay และ server ได้ผลเท่ากัน
6. **เซฟเก่าเปิดได้** แปลงครั้งเดียวตอนโหลด (storage version 5) แล้วเล่นต่อแบบใหม่

## 4. โครงข้อมูลใหม่

### 4.1 ถนน: กราฟจุดต่อ–เส้น (`src/roads/roadGraph.ts`)

```
RoadNode    { id, x, z }                       เมตร บนพื้น (ความสูงอ่านจาก heights)
RoadSegment { id, a, b,                         จุดต่อสองปลาย
              shape: 'line' | 'curve',          curve = Bézier กำลังสาม: c1, c2 (เมตร)
              level 1–8, national, name?, bridge?, piece }
```

- วางถนนตัดถนนเดิม → แบ่งเส้นเดิมที่จุดตัดเป็นสองเส้น + จุดต่อใหม่ **รูปเดิมไม่เปลี่ยน** (ตัดตรงจุดบนเส้นโค้งเดิมพอดี)
- จุดต่อที่มีเส้นเดียว = ปลายถนน, 3+ เส้น = ทางแยก รูปทางแยกคิดจากจุดต่อ (ใช้ `roadJunctions.ts` ต่อ)
- ความกว้างจากระดับถนน (`REAL_WIDTH_M` เดิม)
- ค้นหาเร็วด้วยดัชนีพื้นที่ (R-tree: `rbush`, MIT) สำหรับดูด ชน และเลือก

### 4.2 อาคาร: ชิ้นที่มีตำแหน่งจริง (`src/buildings/placedBuildings.ts`)

```
PlacedBuilding { id, kind, x, z, rot, w, d,     เมตร: กลาง มุม กว้าง ลึก (รูปฐานสี่เหลี่ยมหมุน)
                 segment, along, side,           ผูกกับถนน: เส้นไหน ห่างจากปลาย a กี่เมตร ฝั่งไหน
                 level, sort... }                ข้อมูลเดิม (civicKinds, powerKinds ฯลฯ ย้ายมาอยู่ที่นี่)
```

- วาง = เลือกเส้นถนน + ระยะตามถนน + ฝั่ง หน้าอาคารชิดขอบถนนพอดี
- ตรวจชนด้วยรูปฐานจริง (สี่เหลี่ยมหมุน กับ ถนน อาคารอื่น ขอบเขตที่ดิน) กรอบแดง = รูปฐานจริง
- ถนนถูกตัดหรือรื้อ อาคารไม่ขยับ (เก็บตำแหน่งตัวเอง) แค่ "ไม่ติดถนน" ซึ่ง simulation รู้จากช่องอยู่แล้ว

### 4.3 โซน: ช่องย่อยผูกกับเส้นถนน (`zoneCells.ts` เดิม เปลี่ยนคีย์)

```
คีย์ช่องย่อย = segment + ฝั่ง + ลำดับตามถนน (ช่องละ 4 ม.) + แถว 0–3
```

- เส้นถนนถูกแบ่งที่จุดตัด → คีย์ของสองส่วนคิดจากระยะบนเส้นเดิม ช่องย่อยไม่หาย ไม่ขยับ
- แปลง (plot) ยังเป็นค่าช่อง 16 ม. ตามเดิม (`syncCellPlots`) ในขั้นนี้

### 4.4 ช่องที่สร้างจากของ (raster)

| ของ | กติกาเป็นช่อง |
|---|---|
| ถนน | ช่องที่ "ตัวถนน" (ความกว้างจริง) ผ่านกลางช่องหรือกินพื้นที่ ≥ 30% เป็นช่องถนน รูปช่อง (ตรง/โค้ง/แยก) จากช่องข้าง ๆ เหมือนเดิม; `roadLevels`, `roadPieces` เขียนจากเส้น |
| อาคาร | ช่องที่รูปฐานทับ ≥ 50% เป็นของอาคาร (BNCNBIT ฯลฯ) ช่องกลาง (ZONEBIT) = ช่องที่จุดกลางอาคารอยู่ |
| โซน | เหมือนเดิม (`PLOT_COVER` 28%) |

ชิ้นแรกของแถว "อาคาร" (21 ต.ค. 2026): โรงไฟฟ้ากินช่องเท่ารูปฐานโมเดลจริง 3 × 3 หรือ 2 × 2 ตามชนิดและยุค แทน 4 × 4 ทุกโรง
(`src/plantBlocks.ts`, `docs/POWER_PLANTS.md`) โรงประปาคง 3 × 3 เพราะโมเดลกว้างเท่านั้นอยู่แล้ว

simulation (ไฟวิ่งตามถนน น้ำตามถนน จราจรเดินตามช่องถนน 4 ทิศ) ได้ช่องถนนต่อกันครบเหมือนวันนี้ กติกาข้อแรกต้องรับประกันว่าถนนที่ต่อกันบนจอ = ช่องถนนที่ต่อกัน 4 ทิศ (เติมช่องมุมเมื่อเส้นเฉียง)

## 5. ขั้นตอน (แต่ละขั้นเล่นได้ ทดสอบได้ commit ได้)

### ขั้น 0: เตรียม (เล็ก)
- 0.1 แก้บั๊กคีย์ช่องย่อยตอนวางถนน (`cityCommands.ts` ใช้สูตร 4×4 ต่อช่อง แต่คีย์จริงเป็นตาราง 1 ม.)
- 0.2 `src/units.ts`: เมตร/ช่อง/หน่วย 3D ที่เดียว แทน `/10` ที่ฝังอยู่
- 0.3 รวมการทดสอบ "เป็นถนนไหม" ที่มี 5–6 แบบ (`isRoadTile`, `carriesWater`, `isLineRoad` …) ให้มีชื่อชัดว่าแต่ละแบบนับอะไร
- 0.4 test: เมือง real-scale (ขอนแก่น) ใน `test/cityCore.ts` replay (วันนี้ test ใช้แต่แผนที่ทั้งจังหวัด โซนและช่องย่อยไม่เคยถูกทดสอบ)

### ขั้น 1: ถนนเป็นเมตร
- 1.1 `roadGraph.ts` (ไม่มี DOM, รันใน Node ได้): เพิ่มเส้น แบ่งที่จุดตัด รวมจุดต่อใกล้กัน (< 0.5 ม.) ลบเส้น ดัชนีพื้นที่ การคำนวณจุดตัดแบบแม่น (`robust-predicates`)
- 1.2 `roadRaster.ts`: กราฟ → ช่องถนน + `roadLevels` + `roadPieces` (simulation ไม่ต้องรู้ว่าเปลี่ยน)
- 1.3 คำสั่งใหม่ `{type:'road', points:[[x,z]...] เมตร, shape, level}` หนึ่งคำสั่งต่อหนึ่งเส้น (วันนี้หนึ่งคำสั่งต่อช่อง) ราคา = ความยาวจริง × ราคาต่อเมตร
- 1.4 ภาพ 3D วาดจากกราฟตรง ๆ (ไม่คิดเส้นจากช่องอีก): `roadCurves.ts`, `roadBuild.ts`, worker อ่านกราฟ; ป้ายชื่อถนนผูกกับเส้น
- 1.5 เครื่องมือวาดใหม่: ตรง, โค้ง (ลากจุดคุม), ต่อเนื่อง, อิสระ; ตัวอย่าง = ผลจริง; ป้ายบอกความยาว (ม.) มุม ราคา; Shift ปิดดูด; รถแมคโครรื้อทีละเส้นหรือตัดช่วง; อัปเกรดทีละเส้น
- 1.6 เซฟ version 5: เก็บกราฟ (`roads`), ช่องถนนยังเก็บเหมือนเดิมเพื่อเปิดในโค้ดเก่าได้; แปลงเซฟเก่า: สร้างกราฟจากเส้นที่วาดได้วันนี้ (`networkOf().frozen` + `roadLines`) ครั้งเดียว
- 1.7 undo ทั้งเส้น (กราฟก่อน/หลัง)
- เสร็จขั้น 1 เมื่อ: วาดถนนทุกโหมดในขอนแก่นแล้วถนนอยู่ตรงที่วาด, ไฟ/น้ำ/จราจรเหมือนเดิม (test เทียบ), เซฟเก่าเปิดได้, 60 fps เท่าเดิม

### ขั้น 2: อาคารเป็นเมตร
- 2.1 `placedBuildings.ts` + คำสั่ง `{type:'build', tool, segment, along, side}` (หรือ x, z, rot เมื่อไม่ติดถนน)
- 2.2 ช่องของอาคารคิดจากรูปฐาน (ข้อ 4.4) แทน `buildBuilding` x--, y--
- 2.3 ตรวจชนด้วยรูปฐาน แทน `placeProblem` แบบช่อง + `lotRects` + `aroundCorners` (ลบสามอย่างนี้ทิ้งได้)
- 2.4 ภาพ 3D วางโมเดลจากตำแหน่งจริง (`TileSnapshot.againstRoad`, `poseToKeep`, `keepBuildingPoses` ไม่ต้องใช้แล้ว)
- 2.5 เครื่องมือย้ายอาคาร (ลากตามถนนทีละ 1 ม.) และหมุนเมื่อไม่ติดถนน

- 2.7 `src/objects/` (CityObject) อ่านจาก `buildings` แทนการสแกนช่องทุกเดือน

### ขั้น 3: โซนเป็นเมตร
- 3.1 คีย์ช่องย่อยผูกกับเส้นถนน (ข้อ 4.3) แปลงคีย์เดิม
- 3.2 แปรงทาโซนเป็นเมตร (วงกลม/สี่เหลี่ยม/ตามถนน) บนช่องย่อย
- 3.3 อาคารที่โตบนแปลงมีขนาดตามช่องที่ทา (ตึกแถว 1×4 ช่อง, บ้าน 3×4 ช่อง) หันหน้าตามเส้นถนน
- 3.4 (ภายหลัง) simulation นับโซนตามพื้นที่ช่องย่อย แทนต่อช่อง 16 ม.

## 6. เทคโนโลยีใหม่ (เป้า 4 ดาวขึ้นไป)

เลือกเฉพาะที่ผู้เล่นรู้สึกได้: ลื่น สวย ตอบสนองทันที เซฟไม่หาย

| เทคโนโลยี | ใช้ทำอะไร | ได้อะไร | เมื่อไร |
|---|---|---|---|
| **Simulation ใน Web Worker** | ย้าย `CityCore` ไปรันนอกหน้าจอ (โค้ด simulation ไม่มี DOM อยู่แล้ว) ส่งช่องที่เปลี่ยนกลับมา | หน้าจอไม่กระตุกตอนเมืองใหญ่คิดเดือน ปีละครั้ง | หลังขั้น 1 |
| **SharedArrayBuffer** | ช่องแผนที่ใช้ร่วมกันระหว่าง worker กับหน้าจอ ไม่ต้องคัดลอก | ส่งข้อมูลเร็ว | กับ worker (ต้องตั้ง header COOP/COEP ใน nginx) |
| **WebGPU** (`WebGPURenderer` + TSL ใน three.js 0.186 ที่มีอยู่แล้ว) มี WebGL2 สำรอง | วาดเมือง, compute shader คัดของที่มองไม่เห็นบน GPU | ของบนจอได้มากขึ้นหลายเท่า เงาและแสงสวยขึ้น | ขั้นแยก หลังขั้น 2: ต้องเขียน shader ที่แก้ด้วย `onBeforeCompile` ใหม่เป็น TSL ทั้งหมด |
| **BatchedMesh / instancing ทั้งเมือง** | อาคารยุคและต้นไม้ทั้งหมดเป็น draw call ไม่กี่ครั้ง | 60 fps บนโน้ตบุ๊กการ์ดออนบอร์ด | **ทำแล้ว 21 ต.ค. 2026:** อาคารยุคแบบเดียวกันทั้งเมืองวาดรวมกัน (`src/render3d/city/pools.ts`) เมือง 3,000 แปลง draw call 531 → 152; RENDERER_SPEC §8B |
| **LOD + impostor** | อาคารไกลเป็นรุ่นเบา/ภาพแบน | เห็นทั้งเมืองได้โดยไม่ช้า | **ทำแล้ว 21 ต.ค. 2026 (LOD):** รุ่นเบาจาก meshoptimizer คงสันคม เปลี่ยนเมื่อต่างไม่ถึงหนึ่งพิกเซล (`src/render3d/city/lod.ts`) เมือง 3,000 แปลง 19.6 → 4.5 ล้านสามเหลี่ยม GPU 32 → 14–19 ms; ภาพแบน (impostor) ยังไม่ทำ |

| **rbush + robust-predicates** | ดัชนีพื้นที่และจุดตัดแบบแม่น | ดูด/ชน/เลือกเร็วและไม่พลาดที่มุมแคบ | ขั้น 1.1 |

| **Playwright** | เล่นเกมอัตโนมัติในเบราว์เซอร์จริง ถ่ายภาพเทียบ วัด fps | จับบั๊ก "ถนนขยับ" ก่อนถึงมือผู้เล่น | เริ่มขั้น 0 |
| **PWA** (service worker) | ติดตั้งเป็นแอป เล่นออฟไลน์ โหลดครั้งต่อไปเร็ว | ประสบการณ์เหมือนเกมติดตั้ง | หลังขั้น 1 |
| **WASM** (Rust) | จุดคอขวดที่วัดแล้วช้า เช่น หาเส้นทางจราจร raster เมืองใหญ่ | เร็วขึ้นหลายเท่า | เมื่อวัดแล้วจำเป็น (ขั้น 4) |

ตัวชี้วัดที่จะวัดทุกขั้น (Playwright + เมืองขอนแก่นเต็มเมือง):
- 60 fps บนโน้ตบุ๊กการ์ดจอออนบอร์ด, เฟรมช้าสุดไม่เกิน 50 ms ขณะเมืองคิดเดือน
- เปิดเมืองภายใน 5 วินาที
- คลิกแล้วเห็นผลภายใน 1 เฟรม, ภาพตัวอย่าง = ผลจริง 100%
- ไม่มีของที่วาดแล้วขยับเอง (test อัตโนมัติ: วาด → เซฟ → โหลด → เทียบตำแหน่งทุกชิ้นเป็นเมตร; ถนนและรางมีแล้ว `test/roadsStay.ts`, คลองใน `test/canals.ts`, อาคารใน `test/buildingSave.ts`)

## 7. ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | รับมือ |
|---|---|
| ถนนเฉียงเป็นช่องแล้วขาดตอน simulation เดินไม่ผ่าน | กติกา raster เติมช่องมุมให้ต่อกัน 4 ทิศ + test ทุกมุม 0–90° |
| เซฟเก่าแปลงแล้วถนนเปลี่ยนรูป | แปลงจากเส้นที่วาดอยู่จริงวันนี้ + test เทียบภาพก่อน/หลัง |
| คำสั่งเดิมใน log (`tool x,y` ทีละช่อง) | ยังรับได้ (แปลงเป็นเส้นสั้น) เพื่อ replay เก่า |
| WebGPU ยังไม่มีในบางเครื่อง | WebGL2 สำรองเสมอ ตัดสินตอนเปิดเกม |
| งานใหญ่กินเวลา | ทำทีละขั้น ทุกขั้นเล่นได้และ commit แยก |

## 8. ที่เจ้าของต้องตัดสิน (ระหว่างทาง)

- ระยะดูดที่สบายมือ (เริ่มที่ 14 px) และมุมดูด (15°/45°/90°)
- เปิดให้ย้ายอาคารหลังวางแล้วไหม (ขั้น 2.5) ราคาเท่าไร
- เซฟเก่าแปลงอัตโนมัติ (แนะนำ) หรือเก็บไว้แบบเดิม
- ลำดับเทคโนโลยี: worker + IndexedDB ก่อน (แนะนำ เพราะเกมลื่นและเซฟปลอดภัยทันที) หรือ WebGPU ก่อน
