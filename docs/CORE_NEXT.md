# core รุ่นต่อไป และ "เล่นได้ 80%" ก่อนขึ้นออนไลน์

เขียน 15 ต.ค. 2026 หลังเจ้าของถามว่า "หรือต้องเขียน core เกมส์ใหม่นะ" และ "ฉันต้องมั่นใจว่า เล่นได้ 80% ก่อนถึงจะขึ้น"
เอกสารนี้เป็นข้อเสนอให้เจ้าของตัดสินใจ ยังไม่ได้เริ่มทำ

## ทำไมงานถึงยาก

core ของ micropolisJS คิดว่าเมืองคือตารางช่อง ช่องละหนึ่งอย่าง แต่ PhaiCity อยากเป็นเมืองจริงขนาดจริงแบบ Cities: Skylines
ทุกเรื่องที่เจอวันนี้มาจากความต่างนี้:

| เรื่องที่เจอ | สาเหตุจากตารางช่อง |
|---|---|
| ถนนหักงอ ทางแยกเป็นแผ่นกลม | ถนนเก็บเป็นช่อง ต้องเดาเส้นโค้งจากขั้นบันไดของช่อง |
| อาคารต้องมี "ตำแหน่งชิดถนน" แยกจากช่อง | อาคารผูกกับช่อง 16 ม. แต่ภาพวางอิสระ |
| ช่องเขต 2 ม. กับแปลง 16 ม. สองระบบ | ตัวจำลองนับเขตทีละช่อง 16 ม. |
| เล่นทั้งอำเภอไม่ได้ ต้องใช้กรอบที่ขยายได้ | micropolisJS เก็บทุกช่องเป็น object (`src/gameMap.js`) ตัวจำลองไล่ทุกช่องทุกรอบ |
| ไฟฟ้า น้ำ ต้องไหลผ่านช่อง | การจำลองเดินทีละช่อง |

## ข้อเสนอ: เปลี่ยนทีละส่วน เกมเล่นได้ทุกขั้น

1. **แผนที่เป็นตารางตัวเลข (ราว 1–2 รอบทำงาน):** `src/gameMap.js` เก็บทุกช่องใน `Uint16Array` แบบ Micropolis ต้นฉบับ
   ค่าช่องกับ flag อัดใน 16 บิตอยู่แล้ว ฟังก์ชันภายนอกเหมือนเดิม `getTile()` คืนตัวแทนที่เขียนกลับลงตาราง เซฟไม่เปลี่ยน
   วัดก่อนและหลังด้วย `test/coreBenchmark.ts` ผล: หน่วยความจำลดมาก กรอบเล่นใหญ่ขึ้นได้
2. **ถนนเป็นเส้นกับจุดต่อ (graph):** ถนนเก็บเป็นจุดต่อและเส้นโค้งจริง ช่องถนนสร้างจากเส้น (ให้ตัวจำลองเดิมใช้ต่อ)
   ตัววาด ทางแยก ช่องเขต ไฟฟ้าและน้ำอ่านจากเส้นตรงๆ แทนการเดาจากช่อง
3. **อาคารเป็นวัตถุมีพิกัดจริง:** ตำแหน่ง ทิศ ขนาดตามโมเดล ช่องเขต 2 ม. รวมเป็นแปลงแล้วอาคารงอกบนแปลง
   (`docs/ZONE_CELLS.md` ขั้น 2) แทนแปลง 16 ม.
4. **การจำลองบนตารางหยาบ:** มลพิษ ราคาที่ดิน อาชญากรรม การจราจร คิดเป็นช่องละ 64–128 ม. ไล่วัตถุแทนการไล่ทุกช่อง
5. **ทั้งอำเภอในแผนที่เดียว:** เมื่อ 1–4 เสร็จ กรอบเล่นเหลือแค่การซื้อที่ดิน

ลำดับที่แนะนำ: 1 ก่อน (เล็ก เสี่ยงน้อย ได้ผลทันที) แล้ว 2 ซึ่งแก้ปัญหาที่เห็นบ่อยที่สุด
