# ผลแก้ภาพ 3D กระพริบ — 12 ต.ค. 2026

ยืนยันสาเหตุสองข้อ: ชุดรายละเอียดถูกเลือกใหม่ตามระยะทุกเฟรมโดยไม่มี hysteresis และระบบคุณภาพเรียก setPixelRatio หลัง render โดยไม่วาดซ้ำ ทำให้ paint จบด้วย canvas ที่เพิ่งถูกล้าง

ใช้เทสต์ควบคุม batch ที่ขอบรัศมี/งบ/ดิน โดยขยับ target ครั้งละ 2 เมตรสลับสองตำแหน่ง 200 เฟรม เพื่อแยกการสลับกลับไปกลับมาจากการเข้า/ออกพื้นที่ตามปกติ และมีเทสต์ pan ต่อเนื่อง 400 เมตรที่ batch ซึ่งกำลังออกจากพื้นที่สลับเพียงครั้งเดียว

| การวัด 200 เฟรม | ก่อนแก้ | หลังแก้ |
|---|---:|---:|
| ขอบรัศมี: จำนวนสลับของ batch | 199 | 1 |
| ขอบงบ: จำนวนสลับรวมสอง batch | 398 | 0 |
| รายละเอียดดิน: จำนวนสลับของ batch | 199 | 1 |
| DPR ระหว่าง target เคลื่อน (จำลอง render 24 ms) | 3 | 0 |
| ลำดับท้าย paint เมื่อปรับ DPR | render → resize | render → resize → render |

เปลี่ยนการเลือกเป็น hysteresis 25 เมตร และให้ batch เดิมได้เปรียบระยะ 25 เมตรก่อนแบ่งงบใหม่ ชุดที่ออกต้อง fade จบก่อนให้ชุดใหม่ใช้งบ สลับภาพและเงาด้วย screen-door fade 350 ms โดยใช้ geometry ร่วมกันตามเดิม พื้น terrain.dirt ใช้ผิวเดิมตลอด เปลี่ยนเฉพาะหญ้า/หินแบบ fade และส่งเฉพาะบัฟเฟอร์ fade ระหว่างช่วงเปลี่ยนภาพ

ระบบคุณภาพรอหลังกล้องหยุดอย่างน้อย 1 วินาที เปลี่ยนได้อย่างมากหนึ่งครั้งต่อ 3 วินาที ลดเมื่อ CPU frame time เฉลี่ยเกิน 22 ms เพิ่มเมื่อเฉลี่ยต่ำกว่า 9 ms ต่อเนื่อง 10 วินาทีและอยู่ระดับเดิมอย่างน้อย 10 วินาที ล้างประวัติหลังทุกการเปลี่ยนทั้ง DPR และ drawBudget และ render ซ้ำทันทีใน paint เดียวกันหลัง setPixelRatio ลด drawBudget ต่อได้เมื่อ DPR ถึง 1 โดยมีค่าต่ำสุด 60

navigation.pan(dx, dy, height) ยังเป็น public และเพิ่ม CityView3D.pan(dx, dy) สำหรับผู้เรียกจากเกม โดยไม่แตะ src/game.js

ตัวเลขหลังแก้เป็นรอบที่โหลดโมเดลตลอดเส้นทางแล้ว วัดด้วย performance.now ใน Gallery บนเครื่องที่ใช้ทำงานนี้ ไม่ใช่การวัด laptop ของเจ้าของโดยตรง จำนวนสลับในเส้นทางยาวรวมการเข้า/ออกพื้นที่และการแบ่งงบตามปกติ จึงแยกจากเทสต์ขอบที่ตรวจการสลับกลับไปกลับมา ระบบยังปรับงบจากภาระเฟรม จึงไม่ได้ตรึงระดับรายละเอียดให้เหมือนกันทุกขนาด canvas

ตัวนับ renderer ที่มุมเริ่มต้นอ่านได้ 366 draw calls; หลังเส้นทาง 1920×1080 อ่านได้ 193 draw calls เฟรมแรกของรอบสุดท้ายใช้ 1,606 ms ไม่พบ WebGL shader error หลังโหลดตลอดเส้นทางและตรวจซ้ำ

ภาพ city-motion-after.png แสดงผลรอบ 1199×502; การจับภาพเต็มหน้าเปลี่ยนขนาด canvas ชั่วคราว ดังนั้นขนาด/เวลาใน HUD ปัจจุบันอาจต่างจากสถิติ 10 วินาทีที่คงอยู่ด้านบน

การตรวจสอบ:

- npm run build ผ่าน; มีคำเตือนเรื่องขนาด bundle/asset ตาม output ของ webpack
- เทสต์รวมตรวจ 3,658 ข้อ ทุกกลุ่มที่ไม่เกี่ยวกับไฟล์ระหว่างแก้ผ่าน รวมโมเดลทั้งหมดและ playthrough
- รอบรวมเริ่มระหว่างแก้ไฟล์ จึงพบเทสต์ renderer ที่ใช้ dependency จาก cache ของรุ่นระหว่างแก้ และมี timeout ตรวจ texture ขณะรันงานหนักพร้อมกัน
- รันซ้ำหลังไฟล์นิ่งด้วย `npm test -- --runInBand test/bounds.ts test/render3d/city-motion.test.ts test/render3d/city.test.ts test/render3d/materials.test.ts --coverage=false`: 82 ผ่าน / 2 ล้มจาก 84 ข้อ เหลือเฉพาะ zero-width/zero-height ใน bounds.ts ที่คู่มือระบุว่าเป็นปัญหาเดิม โดย renderer ผ่าน 65/65 ข้อด้วย timeout ปกติ
- git diff --check ผ่าน ตรวจเส้นทางไฟล์และ license header เดิมแล้ว ไม่แก้ไฟล์ shared, เกม, simulation, UI เกม หรือข้อมูลเมือง
