# PhaiCity 3D: ทำให้ภาพในเกมใกล้ concept (ยุค 1–3)

18 ต.ค. 2026 · งานวิเคราะห์เท่านั้น ไม่ได้แก้โค้ดหรือโมเดลของเกม ทุกไฟล์ในงานนี้อยู่ใน `assets/review/`

ภาพเป้าหมาย: `assets/concept/era{1,2,3}_{A_house,B_town,C_vehicles}.jpg` (ยุค 4 มีแค่ `era4_A_house.jpg` ส่วนยุค 5 ยังไม่มี จึงยังไม่ได้ใช้ตัดสิน)

## สรุปสั้น

- **ปัญหาหลักอยู่ที่ตัวเรนเดอร์** concept เป็นภาพประกอบลงสีเรียบ (cel shading) มีเส้นขอบหมึก แดดอุ่นส่องมาจากขวา และเงาเป็นสีม่วงลาเวนเดอร์
  ตัวเรนเดอร์ตอนนี้ไปอีกทางหมด คือ PBR + ภาพถ่าย texture + HDRI + ACES ใช้หมอกสีฟ้า และวางดวงอาทิตย์ไว้หลังกล้อง
  หน้าทดลอง (`lighting-lab.html`) ใช้โมเดลชุดเดิมทุกชิ้น เปลี่ยนแค่ค่าตั้งของตัวเรนเดอร์ ก็ได้ภาพที่เข้าใกล้ concept มาก (`compare_lab_before.png` → `compare_lab_after.png`)
- **โมเดลเป็นปัญหารอง แต่ยังต้องทำ** ที่ต้องแก้คือบ้านทรงยุโรป ต้นไม้แบบแผ่นใบ (leaf card) และสีที่ฝังไว้ในโมเดลเอง
- **3 อย่างที่ควรทำก่อน** (ได้ผลมากที่สุด ลงแรงน้อย ไม่ทำให้เกมช้าลง)
  1. ย้ายดวงอาทิตย์ไปทางขวาของมุมกล้องเริ่มต้นที่มุมเงย ~46° และตั้งเวลาให้เป็นกลางวันคงที่ เลิกใช้รอบกลางวัน–กลางคืน 180 วินาทีเป็นค่าเริ่มต้น
  2. ใช้ชุดแสง "แดดอุ่น + เงาม่วง" เอา HDRI ออกจากตึก เลิกใช้ ACES และเปลี่ยนหมอกกับท้องฟ้าเป็นโทนทราย
  3. เปลี่ยนวัสดุทั้งคลังเป็น `MeshToonMaterial` 3 ระดับ ตัด texture ภาพถ่ายออก แล้วใช้แผงสีใหม่ตาม `materialKey` (เส้นขอบเก็บไว้ทำทีหลัง เพราะหนักเครื่องที่สุด)
- **คัดแยกโมเดล** ในแกลเลอรีมี 203 รายการ ตัดโมเดล debug ออก 2 ชิ้น เหลือ 201
  - (ก) ใช้ได้เลย **90 ชิ้น**
  - (ข) รูปทรงดี แค่ต้องปรับสีเข้าแผงสี **80 ชิ้น**
  - (ค) ต้องปั้นใหม่ **31 ชิ้น**
  
  คนเดินถนน (`pedestrians.ts`) ไม่อยู่ในแกลเลอรี แต่ควรนับอยู่ในกอง (ค)

## ขั้นที่ 1 ตัวเรนเดอร์ตอนนี้ตั้งค่าอะไรไว้

ที่มา: `src/render3d/city/index.ts`, `camera.ts`, `sky.ts`, `src/render3d/materials/library.ts` และแกลเลอรี `src/render3d/gallery/gallery.ts`

| เรื่อง | ค่าในเกม (`CityView3D`) | ค่าในแกลเลอรี |
|---|---|---|
| Renderer | `WebGLRenderer({antialias:true, preserveDrawingBuffer:true})`, pixel ratio ≤ 1.25 ปรับเองตามความเร็ว (ต่ำสุด 1) | `antialias, alpha` |
| three.js | 0.186.1 | เหมือนกัน |
| Tone mapping | `ACESFilmicToneMapping`, exposure 1 | ACES |
| Color space | `SRGBColorSpace` | sRGB |
| แดด | `DirectionalLight(0xffe4bc, 3.3)` ทิศตาม `sunAngle` วางไว้ที่ `target + (cos a·260, max(120, sin a·400), +160)` ซึ่ง **z = +160 ข้างเดียวกับกล้อง** (มุมกล้องเริ่มต้นตั้งที่ heading 0 กล้องอยู่ทาง +z) ที่ a = 0.35π ดวงอาทิตย์อยู่หลังกล้องเยื้องขวา เงย ~58° | `DirectionalLight(0xffe3b0, 3.4)` มีแถบเลื่อนมุมเงย ค่าเริ่ม 55° |
| แสงรอบตัว | `HemisphereLight(sky 0xd7edff, ground 0xb5a385, 1.25)` | `HemisphereLight(0xc6e6ff, 0x9a805c, 1.25)` |
| IBL | HDRI `kloofendal_43d_clear_puresky_1k.hdr` ผ่าน PMREM เป็น `scene.environment` | HDRI เดียวกัน |
| กลางวัน/กลางคืน | `dayNightMode='auto'` รอบละ `CYCLE_DURATION=180` วินาที **ไม่มีโค้ดส่วนไหนเรียก `setDarkMode`** เกมจึงเริ่มตอนรุ่งเช้า (มุมเงย 0) แล้วดวงอาทิตย์ก็หมุนรอบทุก 3 นาที กลางคืนมีสีของตัวเอง (`cSunNight` และอื่น ๆ) | ไม่มีรอบ (เลือกกลางคืนได้) |
| เงา | `shadowMap.type = PCFSoftShadowMap` แต่ **r186 ถอด PCFSoft ออกแล้ว** (คอนโซลเตือน "PCFSoftShadowMap has been removed. Using PCFShadowMap instead.") จึงกลายเป็น PCF ธรรมดา · map 1024² · bias -0.00035 · normalBias 0.06 · กล้องเงาครอบ ±(ระยะกล้อง×0.58) จำกัดที่ 85–340 ม. เท่ากับ 0.17–0.66 ม. ต่อ texel | `PCFShadowMap` 1024² |
| วัสดุ | `MeshStandardMaterial` ประมาณ 40 key ใน `library.ts` ใส่ texture PBR 1K (color/ORM/normal) จาก Poly Haven/ambientCG แบบ lazy · กระจกเป็น `MeshPhysicalMaterial` (ในเมืองปิด transmission ไว้ใน `cityWorldMaterial`) · ยานพาหนะใช้ `vehicleMaterial()` · ทั้งโค้ดมี `MeshStandardMaterial` 80 จุด, Physical 11, Lambert 12, Basic 14 | เหมือนกัน |
| หมอก | `Fog(0xc8dde2, 900 + d·0.9, 5500 + d·1.5)` ระยะขยับตามระยะกล้อง (แผนที่เมืองจริง) | `Fog(horizon, 180–400, 1400)` |
| พื้นหลัง | `scene.background = 0xc8dde2` + `SkyDome` (zenith 0x4f8fd0, horizon 0xd5e6ef, มีเมฆ) | ล้างพื้นหลังโปร่งใส แล้ว CSS เป็นสีเทาอ่อน |
| กล้อง | `PerspectiveCamera` FOV 38°, pitch เริ่ม 55°, ระยะ 240, heading 0 (มุม 2D ใช้ FOV 2°) | Perspective 38° + OrbitControls |

## ขั้นที่ 3 ต่างจาก concept ตรงไหน

ป้าย: **[เรนเดอร์]** = ค่าตั้งหรือโค้ดของตัววาด · **[โมเดล]** = รูปทรง สี หรือวัสดุของแต่ละโมเดล

1. **ลายภาพคนละแบบ** [เรนเดอร์]
   - concept เป็นภาพลงสีเรียบ 2–3 ระดับ มีเส้นขอบน้ำตาลเข้ม (#3B1E10)
   - เกมเป็น PBR + texture ภาพถ่าย ไม่มีเส้นขอบ
   
   ข้อนี้คือช่องว่างที่ใหญ่ที่สุด และแก้ได้ที่วัสดุกลางกับ post-process โดยไม่ต้องปั้นโมเดลใหม่
2. **ทิศแสง** [เรนเดอร์]
   - concept: แดดมาจากขวาของภาพ เยื้องมาทางคนดูเล็กน้อย เงาจึงตกไปทางซ้ายล่าง ด้านขวาของตึกสว่าง ด้านซ้ายมืด
   - เกม: ดวงอาทิตย์อยู่หลังกล้อง หน้าตึกที่หันหาคนดูสว่างเท่ากันทุกด้าน เงาไปซ่อนหลังตึก ภาพจึงแบนและดูไม่ออกว่าตึกสูงแค่ไหน (`current_town.png` แทบไม่เห็นเงาเลย)
3. **แสงไม่คงที่** [เรนเดอร์] รอบ 180 วินาทีทำให้สีทั้งเมืองเปลี่ยนตลอด ช่วงแรกของทุกเกมเป็นรุ่งเช้า (สีส้มอมม่วง) ทั้งที่ concept เป็นบ่ายแก่สีทองคงที่
4. **สีเงา** [เรนเดอร์]
   - concept: เงาเป็นสีม่วงลาเวนเดอร์ เงาบนพื้นทราย #72739D ส่วนด้านเงาของพื้นดิน #E2A56B กลายเป็น #886A70 คือเบนไปทางม่วง ไม่ใช่แค่มืดลง
   - เกม: เงาเป็นสีเทาอมฟ้าอ่อน ๆ จาก hemisphere sky 0xd7edff กับ HDRI ฟ้า
5. **ความเข้มของเงา** [เรนเดอร์] แสงรอบตัว (hemi 1.25 + IBL) แรงเกินไป ด้านเงามืดกว่าด้านแดดแค่นิดเดียว ภาพเลยซีด ส่วนใน concept ด้านแดดกับด้านเงาต่างกันชัด
6. **ความคมของเงา** [เรนเดอร์]
   - concept: เงาขอบคม นุ่มนิดเดียว
   - เกม: PCF ธรรมดาเพราะ PCFSoft ถูกถอดแล้ว map 1024² บนพื้นที่สูงสุด 680 ม. ขอบเงาจึงเป็นก้อนหยาบเวลาซูมออก และพาดหายเวลาซูมไกล
7. **ความสดของสี** [เรนเดอร์ + โมเดล]
   - ACES ทำให้สีอิ่มน้อยลงและเพี้ยน แดงกลายเป็นส้มอมน้ำตาล [เรนเดอร์]
   - สีโมเดลเองเป็นโทนเย็น/พาสเทล เช่น ผนังม่วงชมพูอ่อน หลังคาซีเมนต์สีเทาฟ้า กระจกฟ้า [โมเดล]
   - concept เป็นโทนอุ่นทั้งภาพ เช่น ไม้สัก ดินเผา ทอง เขียวมะกอก
8. **พื้นหลังและหมอก** [เรนเดอร์]
   - concept: พื้นหลังทรายไล่จาก #E9C999 ถึง #FCD691 (มุมขวาบนสว่าง) ไม่มีหมอก
   - เกม: หมอกฟ้าอ่อน #C8DDE2 กับท้องฟ้าสีฟ้า ทำให้ภาพเย็นและไม่เข้ากับตึกโทนอุ่น
9. **กล้อง** [เรนเดอร์]
   - concept: isometric แบบ orthographic เงย ~35° มุมเฉียง 45°
   - เกม: perspective 38° เงย 55° heading 0 ตารางถนนจึงตั้งตรงกับจอ ไม่เป็นข้าวหลามตัด ตึกด้านขอบจอเอียงออก
10. **texture ภาพถ่ายดูเป็นจุดรก** [เรนเดอร์ + โมเดล] หญ้า กระเบื้อง ยางมะตอย และดินลูกรังมีลายภาพถ่าย 1K ซึ่งพอย่อเหลือไม่กี่พิกเซลก็กลายเป็นจุดรก ส่วน concept ใช้สีเรียบ แล้ววาดลายเป็นเส้น เช่น แนวกระเบื้อง แนวไม้
11. **พื้นดินของเมือง** [โมเดล + เรนเดอร์]
    - เกม: เขียวอ่อนอมเหลือง ปนแผ่นเขียวเข้มของป่าที่เป็นรูปหลายเหลี่ยมขอบแข็ง กับแผ่นทรายซีด ดูยังทำไม่เสร็จ
    - concept: หญ้าเขียวมะกอก #A59630 ทางดินลูกรัง #D1874C และนาข้าวเขียวสด #81D059
12. **ชั้นช่องโซนทับเมืองตลอดเวลา** [เรนเดอร์] ช่องสีเขียวหรือฟ้าโปร่งแสงขนาดใหญ่ทับทั่วย่านใจกลาง (`current_town*.png`) แม้ไม่ได้ถือเครื่องมือ บังตึกและทำให้ภาพไม่เหมือนเมืองจริง
13. **ตึกหายเมื่อซูมออก** [เรนเดอร์ ยังไม่ยืนยันสาเหตุ] ที่มุมกล้องเริ่มต้น เมือง 22,000 คนไม่เห็นตึกสักหลัง เห็นแค่ต้นไม้กับช่องโซน (`current_town_far.png`) ต้องซูมเข้ามาก ๆ ตึกถึงจะโผล่ อาจเป็นเพราะ LOD หรือ `drawBudget` ของแผนที่เมืองจริง หรือโมเดลยังโหลดไม่เสร็จ (รอไปแล้ว 30–60 วินาที) ควรตรวจแยกต่างหาก เพราะไม่ว่าจะปรับแสงแค่ไหน ภาพก็ไม่ใกล้ concept ถ้าตึกไม่ขึ้น
14. **บ้านดูไม่ไทย** [โมเดล]
    - `res.house_1_1 … 3_2` และ `res.block_2_0` เป็นบ้านทรงยุโรป หลังคาจั่วสูงชัน ผนังขาวหรือชมพู ขอบหน้าต่างเขียว
    - บ้านใต้ถุนสูง (`house_0_0/0_1`) มีใต้ถุน บันได และชาน ถูกแล้ว แต่หลังคาเป็นจั่วเรียบ ไม่มีชายคายื่น ไม่มีปั้นลม ไม่มีหลังคาจาก/หญ้าคา
15. **หน้าต่าง** [โมเดล]
    - concept: บานเกล็ดไม้หรือหน้าต่างลายไม้กรอบน้ำตาล
    - เกม: กระจกฟ้าเรียบ ห้องแถวไม้ยุค 2 (`com.block_0_1`) จึงดูเป็นตึกกระจก
16. **ต้นไม้** [โมเดล]
    - concept: มะพร้าวกับกล้วยใบใหญ่ เป็นก้อนชัด มีเส้นขอบ
    - เกม: ใช้แผ่นใบ (leaf card) โปร่ง รูปทรงกระจัดกระจาย พอใส่เส้นขอบก็กลายเป็นลายดำรก (ดู `lab_step6.png`)
17. **สัดส่วนของประกอบฉาก** [โมเดล]
    - concept ขยายของเล็ก ๆ ให้ใหญ่กว่าจริง เช่น คน กระถาง ต้นกล้วย มอเตอร์ไซค์ รถเข็น เสาไฟ ภาพจึงอ่านง่ายแบบไดโอรามา
    - เกม: แผนที่เมืองจริงทำทุกอย่างตามขนาดจริง (16 ม./ช่อง) รถกับคนเลยเล็กมาก
18. **รายละเอียดเล่าเรื่อง** [โมเดล] concept มีกันสาดลายทาง แผงผลไม้ เสาไฟพร้อมสายระโยงระยาง แอร์ แท็งก์น้ำ ตู้กดน้ำ ศาลพระภูมิ ซึ่งบางชิ้นมีแล้ว เช่น `plot.com_2` มีแอร์และแท็งก์น้ำ แต่ส่วนใหญ่ยังไม่มี

### ข้อเสนอเรียงตามความคุ้ม (ผลที่ได้ ÷ แรงที่ลง)

#### 1. ทิศแดดและเวลาคงที่ · ผลมาก · แรงน้อยมาก · ความเร็ว: ไม่เปลี่ยน

ย้ายดวงอาทิตย์ไปทางขวาของมุมกล้องเริ่มต้น เยื้องมาหากล้องเล็กน้อย มุมเงยประมาณ 46° (ในหน้าทดลองคือ (0.62, 0.72, −0.32) เมื่อกล้องอยู่ที่มุม 45°) แล้วให้ค่าเริ่มต้นเป็นกลางวันคงที่ เก็บกลางคืนและรอบวันไว้เป็นตัวเลือก (หรือทำรอบให้ยาวขึ้นมาก แล้วตัดช่วงรุ่งเช้า/ค่ำออกจากเวลาเล่นปกติ)

```ts
// index.ts — the concept's sun: right of the default view, a little toward the camera, 46° up
const SUN_DIR = new Vector3(0.67, 0.72, 0.21).normalize(); // heading 0 looks toward -z
private dayNightMode: 'auto' | 'day' | 'night' = 'day';    // a fixed golden afternoon by default
// render():
this.sun.position.copy(t).addScaledVector(SUN_DIR, 400); this.sun.target.position.copy(t);
```

ทิศแดดผูกกับโลก ไม่ได้หมุนตามกล้อง ถ้าผู้เล่นหมุนกล้อง 180° ภาพจะกลายเป็นย้อนแสง เรื่องนี้ต้องให้คุณเลือก:
- **(ก) ผูกกับโลก** เหมือนจริง (แนะนำ)
- **(ข) หมุนตามกล้อง** เงาตกซ้ายล่างเสมอเหมือนภาพ concept แต่เวลาหมุนกล้องเงาจะเลื่อนตาม

#### 2. ชุดแสง "แดดอุ่น + เงาม่วง", เลิกใช้ ACES/HDRI · ผลมาก · แรงน้อย · ความเร็ว: เบาลงเล็กน้อย

ไม่ต้องสุ่ม IBL จาก PMREM อีก และไม่ต้องโหลดไฟล์ HDR 1K

หลักการ: สีด้านแดด = สีวัสดุ × (แดด + แสงรอบตัว) ≈ สีวัสดุ และสีด้านเงา = สีวัสดุ × แสงรอบตัว ถ้าแสงรอบตัวเป็นลาเวนเดอร์ (#99A3FF ซึ่งใน linear คือ 0.33, 0.37, 1.0) เงาจะเบนเป็นม่วงตรงกับ concept เช่น #E2A56B → ~#886A70

```ts
this.renderer.toneMapping = NoToneMapping;          // palette colours come out as painted (or NeutralToneMapping)
this.scene.environment = null;                      // no HDRI light on buildings (keep it only for water/glass if wanted)
this.scene.remove(this.hemi);
const ambient = new AmbientLight(0x99a3ff, Math.PI); // shade = albedo × lavender
this.sun.color.set(0xd8cf40); this.sun.intensity = Math.PI; // what the lit side adds on top: lit ≈ albedo
```

กลางคืนก็ใช้หลักเดียวกัน คือเปลี่ยนสีแสงรอบตัวเป็นน้ำเงินเข้ม แล้วลดแดดเหลือแสงจันทร์

#### 3. หมอก ท้องฟ้า และพื้นหลังโทนทราย · ผลกลาง–มาก · แรงน้อย · ความเร็ว: ไม่เปลี่ยน

```ts
const haze = new Color(0xe9c999);                  // sand, the concept's backdrop
this.fog = new Fog(haze, this.fogNear, this.fogFar); this.scene.background = haze;
this.sky.setColors(new Color(0xf6d9a4) /* zenith */, new Color(0xfcd691) /* horizon */, haze);
```

แผนที่เมืองจริงมีขอบฟ้า จึงใช้พื้นหลังทรายเรียบ ๆ แบบ concept ไม่ได้ แต่ทำท้องฟ้าโทนทองแทนได้ ส่วนในแกลเลอรีและหน้า "ไดโอรามา" ใช้พื้นทรายไล่สีแบบในหน้าทดลองได้เลย

#### 4. วัสดุ toon 3 ระดับ + แผงสีตาม materialKey · ผลมาก · แรงกลาง · ความเร็ว: เบาลง

shader ง่ายกว่าและอ่าน texture น้อยกว่า

```ts
const ramp = new DataTexture(new Uint8Array([70,70,70,255, 150,150,150,255, 255,255,255,255]), 3, 1, RGBAFormat);
ramp.minFilter = ramp.magFilter = NearestFilter; ramp.needsUpdate = true;
function toon(m: MeshStandardMaterial): MeshToonMaterial {
  const key = m.userData.materialKey as MaterialKey | undefined;
  const t = new MeshToonMaterial({ color: PALETTE[key!] ?? m.color, gradientMap: ramp, side: m.side, alphaTest: m.alphaTest });
  if (m.alphaTest > 0 && m.map) t.alphaMap = alphaOf(m.map); // leaves keep only their cut-out (alpha → green channel)
  return t;
}
```

- **จุดที่ใส่โค้ด:** มีวัสดุ `MeshStandardMaterial` ที่สร้างตรง ๆ ใน 80 จุด ทางที่ง่ายสุดจึงไม่ใช่ไล่แก้ทีละไฟล์ แต่สลับวัสดุครั้งเดียวตอนสร้าง prototype ของแต่ละโมเดล (ฝั่ง worker หรือ `prototypes.ts`) เหมือนที่ `cityWorldMaterial()` ทำอยู่แล้ว
- **วัสดุที่ไม่มี `materialKey`:** สีที่ฝังไว้ในโมเดล (`0x…` หรือ `tint`) จะไม่โดนแผงสี นี่คือที่มาของกอง (ข)
- **ข้อดีที่ได้แถม:** ไม่ต้องโหลด texture ภาพถ่าย 1K ของตึก ยกเว้นใบไม้ ขนาดดาวน์โหลดและหน่วยความจำจะลดลงชัดเจน

#### 5. เงาคมและม่วง · ผลกลาง · แรงน้อย · ความเร็ว: เล็กน้อย

shadow map 2048² ใช้หน่วยความจำเพิ่มจาก 4 MB เป็น 16 MB ส่วนรอบวาดเงายังเท่าเดิม

```ts
this.renderer.shadowMap.type = PCFShadowMap;        // r186 dropped PCFSoftShadowMap (it was silently PCF anyway)
this.sun.shadow.mapSize.set(2048, 2048);             // when the shadow span is past ~150 m
this.sun.shadow.radius = 2;                          // soft edge; check that r186 PCF honours radius, else VSMShadowMap
// snap the shadow camera to its texel grid so shadows do not shimmer while panning
```

สีเงาบนพื้นได้มาจากข้อ 2 อยู่แล้ว ไม่ต้องทำอะไรเพิ่ม

#### 6. กล้องแบบเกือบไอโซ · ผลกลาง · แรงน้อยมาก · ความเร็ว: ไม่เปลี่ยน

ปรับ LOD/ระยะวาดอีกนิด

```ts
const FOV = 24;                       // a longer lens: near-isometric, still perspective down at the street
heading = Math.PI / 4; pitch = 38 * Math.PI / 180; // the concept's diagonal grid and ~35–40° elevation
```

ไม่แนะนำให้เปลี่ยนเป็น orthographic ทั้งเกม เพราะตอนเดินดูระดับถนนต้องการ perspective ข้อนี้เปลี่ยนความรู้สึกของมุมกล้องเริ่มต้นด้วย จึงควรให้คุณลองก่อน

#### 7. เส้นขอบหมึก (post-process ขอบจาก normal + depth) · ผลมาก · แรงกลาง · ความเร็ว: หนักที่สุด

ต้องวาดเรขาคณิตรอบที่สองด้วยวัสดุ normal (draw calls ×2) แล้วตามด้วย full-screen pass อีก 1 รอบ ที่ 1080p บนการ์ดจอในตัวคาดว่าเพิ่ม ~1–3 ms

shader แบบเดียวกับใน `lighting-lab.html`:

```glsl
float dd = abs(d(vec2(1,1))-d(vec2(-1,-1))) + abs(d(vec2(1,-1))-d(vec2(-1,1)));
float nd = length(n(vec2(1,1))-n(vec2(-1,-1))) + length(n(vec2(1,-1))-n(vec2(-1,1)));
float edge = max(smoothstep(.35,.6, dd/max(1.,dc*.004)), smoothstep(.45,.9, nd));
gl_FragColor = linearToOutputTexel(vec4(mix(c.rgb, ink, edge*.92), c.a));
```

ทางที่เบากว่า:
- **(ก)** หา normal จาก depth ของรอบวาดหลัก แล้วใช้แค่ full-screen pass เดียว (ไม่ต้องวาดรอบสอง แต่เส้นตามรอยพับบางจุดจะหายไป)
- **(ข)** อบเส้นขอบลงในโมเดลด้วย `EdgesGeometry(geom, 30°)` แล้วรวมเป็นก้อนต่อ chunk (+1 draw call ต่อ chunk แต่เส้นบาง 1 px)

ใช้กับระบบปรับคุณภาพที่มีอยู่ได้ เช่น เปิดเส้นขอบเฉพาะตอนเฟรมเร็วพอ หรือตอนซูมใกล้

ต้องทำต้นไม้แบบก้อนให้เสร็จก่อน ไม่อย่างนั้นใบแบบแผ่นจะเป็นลายดำรก

#### 8. ชั้นช่องโซนและ LOD · ผลกลาง–มาก · แรงไม่แน่นอน · ความเร็ว: ขึ้นกับการแก้

ไม่ใช่เรื่องแสง แต่บังภาพเมือง ควรแก้ไปพร้อมกัน:
- **ช่องโซน:** แสดงเฉพาะตอนถือแปรงทาโซน ตอนอื่นให้เหลือแค่พื้นที่ย้อมสีจาง ๆ
- **ตึกหายตอนซูมออก:** หาสาเหตุ แล้วทำ LOD ระยะไกลเป็นกล่องสีตามแผงสี แทนการไม่วาดเลย

ข้อเสนอเสริมที่ไม่ได้ทำในหน้าทดลอง:
- **ยก saturation ทั้งภาพ** ผ่าน LUT (full-screen pass, เบา) ไม่จำเป็นถ้าแผงสีถูกตั้งแต่แรก
- **ขอบที่ดินที่ซื้อแล้วเป็นหน้าตัดดิน** ระบบ `cityFrame` ทำให้ขอบเป็นหน้าตัดดินแบบไดโอรามาได้ (ดินด้านสว่าง #D78846 ด้านเงา #7F544B ฐานไม้) เป็นเอกลักษณ์ของ concept ที่ใช้ในเกมได้จริง

### เรื่องที่ต้องให้คุณตัดสิน

1. **หน้าจั่วไทยบนบ้านกับตึกแถว** concept ยุค 1–3 มีปั้นลมปลายงอนบนบ้าน และยุค 3 มีหน้าจั่วประดับใหญ่บนตึกแถว แต่ CLAUDE.md ข้อ 8 ห้าม "เครื่องประดับหลังคาวัดหรือวังบนบ้าน" ปั้นลมกับตัวเหงาเป็นของเรือนไทยปกติ แต่ช่อฟ้า ใบระกา และหางหงส์เป็นของวัด ต้องการให้ระบุว่าบ้านใช้ส่วนไหนได้ ก่อนปั้นบ้านกอง (ค)
2. **ทิศแดด** ผูกกับโลก หรือหมุนตามกล้อง (ขั้นที่ 4 ข้อ 1)
3. **กล้องเริ่มต้น** หมุน 45° (ตารางถนนเป็นข้าวหลามตัดแบบ concept) และใช้เลนส์ยาวขึ้นหรือไม่
4. **ขนาดของประกอบฉาก** จะยอมขยายคน รถ และต้นไม้ให้ใหญ่กว่าจริง (แบบไดโอรามา) ในแผนที่เมืองจริงหรือไม่
